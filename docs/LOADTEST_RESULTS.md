# 負荷テスト結果（開発環境・ローカル）

実行：`node loadtest/run.mjs --clients=25 --duration=600`（サーバーと同一マシン、ループバック。4 vCPU / 16GB、Node 22）。
25 のヘッドレスクライアントが 20Hz でランダム歩行を送信し続け、サーバーは 10Hz で差分配信。

## 10 分間連続（600 秒）

| 指標 | 値 |
|---|---|
| 接続数 | 25 / 25（全時間帯で維持） |
| 参加所要時間 | 25 接続を 2.2 秒で参加完了（80ms 間隔の順次参加） |
| 下り帯域 / クライアント | 平均 4.30 KB/s（≒ 34 kbps）。25 台合計 ≒ 108 KB/s |
| ブロードキャスト遅延 | p50 30 ms / p95 49 ms（送信時刻 → 他クライアント受信。10Hz 配信間隔を含む） |
| サーバー CPU | 平均 約 2%、最大 2.3%（1 コア基準） |
| サーバー RSS | 85 MB → 114 MB で安定（4 分以降増加なし） |
| 切断 | 0 回 / 600 秒 |
| エラー | 0 |

> 本番（Fly.io nrt）では、遅延にネットワーク RTT（教室 Wi-Fi → 東京 で通常 10〜40 ms）が加算されます。
> 実機での再計測は `npm run loadtest -- --url=wss://<app>.fly.dev --clients=25 --duration=600 --class=loadtest` で行えます。

## 60 秒（参考）

| 指標 | 値 |
|---|---|
| 下り帯域 / クライアント | 平均 4.24 KB/s、最大 4.31 KB/s |
| 遅延 | p50 35 / p95 49 / p99 52 / max 54 ms |
| CPU | 平均 2.6% / 最大 4.9% |
| RSS | 平均 86 MB / 最大 91 MB |
| 切断 / エラー | 0 / 0 |

## 見方・目安

- 帯域 4.3 KB/s は 25 人分の位置（x, z, yaw, ts）が 10Hz で届く分。教室 Wi-Fi（数十 Mbps）に対して十分小さい。
- shared-cpu-1x（Fly の最小構成）でも CPU 2% 程度なので、1 台で複数クラスを同時に収容できる見込み。
- 遅延 p95 が 300 ms を超える、または切断が出る場合は、まず Wi-Fi の AP 容量・チャネル干渉を疑う。
  補間バッファ（`client/dist/net-config.js` の `INTERP_DELAY_MS`）を 150〜200 ms に上げると、多少の遅延揺れでも滑らかさを保てる。
