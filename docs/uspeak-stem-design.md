# U-Speak STEM — 大きく作っても勝てる設計（2026-10-01）

**前提：** 対象年齢も市場も狭めない。日本だけでなく世界の、4〜15歳の子どもに向けた「STEM」という大風呂敷で設計する。
いちばんの武器は、創業者が UCLA で天体物理（Astrophysics）を専攻していること。

**この文書の位置づけ：** まだ作らない。作るときの設計図。
市場・競合の数字は前回の調査 `docs/uspeak-stem-research.md` と、今回の追加調査（出典は末尾）による。
【未検証】の数字は、提案書に載せる前に一次資料で確かめること。

## 0. 一枚で

> **「本物の物理と本物の宇宙のデータで、歩いて入れる科学の世界」**
> 子どもは島を歩き、予想して、実験して、測って、**英語で**説明する。
> 結果はサーバーが同じ物理でもう一度計算して確かめるので、子どもにも先生にもごまかせない。
> クラス全員の実験結果が1つのデータになり、それを読むことまでが授業になる。

**勝てる理由は7つ。どれか1つではなく、組み合わせで勝つ（§3）。**

1. **本物の物理・本物のデータ。**
   天体物理の専門家が監修するので、星図・軌道・系外惑星・銀河がすべて本物。
   宇宙を題材にした子ども向けコンテンツの多くはアニメ調にとどまっている。
2. **サーバーが判定する科学。**
   同じ物理をサーバーでも計算し直すので、実験結果を偽れない。評価として信頼できる。
3. **クラスでやる実験。**
   30人の試行を1つのデータにまとめる。1人用の学習アプリにはできない。
4. **英語で科学（CLIL）が最初から入っている。**
   画面は英語が主で、日本語に切り替えられる。日本の英語教室にも、世界の英語圏にも同じ製品で入れる。
5. **入口がすでにある。**
   ツリーベルの英語教室と、U-Speak Roblox。
6. **エンジンがもうできている。**
   島・マルチプレイ・先生コンソール・保護者レポート・AI・英日切り替え。
7. **実験をデータで書ける仕組み。**
   1本あたりの制作コストを下げられる。前回の調査で「理科ユニットの制作費が大きい」が最大のリスクだったので、そこを潰す。

**正直に書いておくこと：** ターゲットは狭めない。ただし、**入っていく順番は決める**（§13）。
全方位に同時に売り出すと、小さいチームではどこにも深く入れない。
「対象は全員、最初に勝ち切る場所は1つ」。この順番を決めることが、大風呂敷を広げても負けない条件。

## 3. 7つの堀（真似されにくいところ）

1. **専門性が要る信頼性。**
   - 軌道は本物のニュートン重力で計算する（エネルギーが狂いにくいシンプレクティック積分）。
   - 光は本物のスペクトル。
   - 系外惑星は、本物のトランジット（惑星が星の前を横切って暗くなる）の光度曲線。
   - 天体物理の専門家が監修していることが、そのまま**ブランド**になる。片手間では作れない。
2. **サーバーが判定する科学。**
   - 実験は「パラメーター＋乱数の種」でサーバーが**同じ結果を再計算**する。
   - これは `kart-drive.js` ですでにやっている作りで、1/120秒の固定ステップなので、どの端末でも同じ物理になる。
   - 子どもが「測った値」を書き換えても、サーバーの値と合わなければ通らない。保護者レポートの数字が信用できる。
3. **クラスのデータ。**
   - 30人がそれぞれ条件を変えて試す（例：振り子の長さ、惑星の重力）。
   - その結果が**クラスの散布図**になり、「ばらつき」と「法則」を読む授業になる。
   - これはマルチプレイのサーバーを持っていないとできない。
4. **CLIL が最初から入っている。**
   - 英語教室にとっては「英語の授業の付加価値」、世界にとっては「英語の科学教材」。**同じ製品が2つの市場の顔を持つ。**
   - 画面ぜんぶの英日切り替えは、もう完成している（2026-10）。
5. **入口がある。**
   - ツリーベル（すでに導入済み）とその先の英語教室・塾。
   - U-Speak Roblox（認知の入口）。
6. **エンジンができている。** §10 の表のとおり、新しく作るのは**実験の層だけ**。
7. **データの好循環。**
   - 子どもの「予想」が貯まると、**よくある思い違いの地図**ができる（例：重い物ほど速く落ちる、と思っている子は何%か）。
   - それが先生への提案と、コンテンツの改善に戻る。使われるほど強くなる。

## 4. 世界の設計（地域＝分野）

**旗艦は COSMOS（宇宙）。** 創業者の専門で、子どもの「すき」がいちばん強い分野でもある
（小中学生の68.4%が宇宙に興味あり。きっかけの64.3%はプラネタリウムなどの体験 [B48]）。

| 地域 | 分野 | 中心の体験 | 今ある島・仕組みの使い回し |
|---|---|---|---|
| **COSMOS**（旗艦） | 天文・天体物理 | 下の §4.1 | 昼夜の時計 → **本物の空**（その日・その場所の星） |
| **FORCE** | 力・運動・エネルギー・波・光 | 振り子、坂、てこ、ばね、音、光の屈折、**カートの物理** | `kart-drive.js`（摩擦・ドリフト・ブースト＝力学そのもの） |
| **LAB** | 物質・化学 | 状態変化・溶解度・酸とアルカリ・燃焼・中和・電気分解・炎色反応（§4.2） | 新しく作る（`chem-core`）。分光器は COSMOS と共有 |
| **LIFE** | 生物・からだ・生態系 | 海の生き物、食物連鎖、植物の成長、からだのしくみ | **つりの 133しゅるいの魚**（図鑑 → 海洋生物学）、ペットの育成 → 生活環 |
| **EARTH** | 地学・天気・**防災** | 天気、火山、地震、津波、川の流れ | 天気 → 気象。日本の強みである防災教育 |
| **MAKER** | 工学・ロボット | 橋をかける、回路、ロボットアーム、ローバー | **BLOCKWILD**（材料と構造）、まちづくり島 |
| **DATA** | データ・AI | クラスのデータを読む・グラフ・予測・AI の仕組み | 先生コンソール・保護者レポートの表示の仕組み |

英語の島（英検・英会話）は**そのまま残す**。STEM の島で使う英語は、英語の島で練習した表現と英検の語彙につなげる。

**1つの体験に3つの深さ**（§5）。
例：軌道の発射台なら、

- Explore：「速く投げると、回る！」
- Investigate：「速さと周期の表を作る」
- Engineer：「静止軌道に乗せる速さを、式とコードで出す」

### 4.2 LAB（化学の実験室）— 家でも学校でもできない実験を、毎日できる

**なぜ仮想の化学室に価値があるか。** 化学は理科の中でいちばん「教室でやりにくい」分野。

- 薬品の準備と片付け、安全管理、時間がかかる。
- 一人ひとりが何度もやり直すことはできない。
- 家ではほぼできない。

仮想なら、**全員が自分の手で、何度でも、失敗しても安全に**できる。
本物の実験を置き換えるのではなく、本物の前後で使う（§8）。

**しくみ：`chem-core`（物質の表と反応の表）**

分子を1つずつ計算するのではなく、**物質の性質の表**と**反応の規則の表**で動かす。
決定的なので、サーバーで同じ結果を再計算して判定できる。

- **物質の表**：状態（固体・液体・気体）、色、密度、溶ける量（温度ごとの溶解度）、pH、燃えるか。
- **反応の表**：混ぜたもの＋条件（温度・量）→ できるもの＋**見えること**（色が変わる・泡が出る・熱くなる・沈殿ができる）。
- **量は保存される**：質量保存の法則がシムの中で必ず成り立つ。中2の「化学変化と質量」がそのまま実験になる。
- **粒子の目（いちばん大事）**：ボタン1つで、ビーカーの中が**分子・イオンの粒の動き**に切り替わる。
  化学でいちばんつまずく「目に見える変化と、目に見えない粒をつなぐ」ところを、見せて分からせる。

**学習指導要領にそのまま当たる実験**

| 学年 | 単元 | 仮想の化学室ですること |
|---|---|---|
| 小4 | 水のすがた | 温めて100℃で沸騰、冷やして0℃で氷。粒の目で、動きが変わるのを見る |
| 小5 | もののとけ方 | 温度を変えて、食塩とミョウバンが何gとけるか → 溶解度のグラフ → 再結晶 |
| 小6 | 燃焼のしくみ | びんの中のろうそく。酸素の割合と、燃えたあとの気体 |
| 小6 | 水溶液の性質 | リトマス紙・BTB・**むらさきキャベツ**で、酸性・中性・アルカリ性を分ける |
| 中1 | 物質のすがた | 密度で物質を見分ける。蒸留。状態変化 |
| 中2 | 化学変化と原子・分子 | 分解・化合・**質量保存**。粒の目で原子が組みかわるのを見る |
| 中3 | 化学変化とイオン | 電気分解、中和の滴定（ちょうど中性になる量を予想 → 測る） |
| 中3 | 化学変化と電池 | 金属の組み合わせと電圧 |

**化学室にしかない体験**

- **炎色反応 → 星の光（COSMOS とつながる）**
  - 金属を炎に入れると色が出る。それを分光器で見るとスペクトルの線になる。
  - **同じ分光器を COSMOS の光の塔に持っていくと、星の光に同じ線が見える。**
  - 「星は、きみの実験室と同じ元素でできている」。宇宙と化学が1本の線でつながる。天体物理の専門家だから組める体験。
- **安全の習慣を身につける**：ゴーグルと手袋をつけないと実験台に立てない。換気、薬品のラベルを読む（英語で）。
  本物の実験室に入る前に、手順が身体に入る。
- **教室ではできない量と時間**：結晶を1週間かけて育てる（実時間で毎日見に来る）。30人が条件を1つずつ変えて、クラスの溶解度曲線を作る。
- **家でできる本物の化学**：むらさきキャベツの指示薬、重曹と酢。保護者の画面に手順を出し、**数字だけ**を入れてもらう。

**判定の例**

- 「60℃の水100gにミョウバンは何gとけるか」を予想させ、サーバーが溶解度の表から答えを出して比べる。
- 中和の滴定は、ちょうど中性になる量をサーバーが計算する。
- 子どもが手元で数値を書き換えても通らない。

### 4.3 STEM ぜんぶを1つの世界で（S・T・E・M の対応）

| | 分野 | 地域 | 中心の体験 |
|---|---|---|---|
| **S** | 物理 | FORCE | 振り子・坂・てこ・ばね・音・光・電気と磁石・カートの物理 |
| **S** | 化学 | **LAB** | 上の §4.2 |
| **S** | 生物 | LIFE | 海の生き物（つりの133しゅるい）・植物の成長・からだ・食物連鎖・遺伝 |
| **S** | 地学・宇宙 | EARTH / **COSMOS** | 天気・地層・火山・地震・**防災**／星・月・惑星・銀河 |
| **T** | 技術・情報 | DATA | プログラミング（実験の道具として）・データ・AI のしくみ・情報モラル |
| **E** | 工学 | MAKER | 橋・塔・回路・ロボット・ローバー。設計 → 作る → 試す → 直す |
| **M** | 数学 | **どの地域にも** | 測る・比・グラフ・統計（クラスのデータ）・10の何乗（宇宙の大きさ）・確率（遺伝） |

- **数学は独立した島にしない。** 実験の「言葉」として、すべての地域に入れる。
  「グラフを読む」「比で考える」「ばらつきを見る」が、実験の中で必要になるから身につく。
- **共通する3つの部品**があれば、どの地域も同じ作りで増やせる。
  - `sim-core`（物理）・`chem-core`（物質と反応）・`eco-core`（個体数の変化）の共有エンジン
  - 実験を JSON で書く仕組み（§6）
  - 予想 → 測る → 説明 の判定（§6）

### 4.4 全体をつなぐ物語：「きみは星のかけらでできている」

地域をばらばらの単元にしないために、**宇宙の歴史を1本の物語**にして全体をつなぐ。天体物理の専門家が作るからこそ語れる物語。

```
ビッグバン（COSMOS）→ 星の中で元素ができる（COSMOS → LAB）
→ 元素が組み合わさって物質になる（LAB）→ 地球ができる（EARTH）
→ 生命が生まれる（LIFE）→ 人が道具を作る（MAKER）→ データで未来を予測する（DATA）
```

- 子どもは地域をめぐるたびに、この物語の章を1つずつ開いていく。今の RPG の「冒険ノート」と同じ形。
- 最後の章は「きみの体の原子は、むかし星の中で作られた」。これが**ブランドの約束**になる。

## 5. 年齢を狭めない仕組み：同じ島・3つの深さ

**英検の島で「間取りは1つ、級で中身が変わる」がうまくいった。** STEM でも同じ形にする。

| 深さ | 目安 | 子どもがすること | 英語 |
|---|---|---|---|
| **Explore** | 4〜7歳 | 触る・見る・くらべる。予想は「どっち？」の2択 | 単語（big / fast / fall） |
| **Investigate** | 8〜11歳 | 予想 → 条件を1つ変える → 測る → 表とグラフ | 文（I think it will… because…） |
| **Engineer** | 12〜15歳 | 式・コード・モデルを作る。誤差を考える | 説明と議論（The data shows…） |

- **同じ部屋に、ちがう深さの子が一緒にいられる。** 兄弟・異年齢のクラス・家庭でも成り立つ。
- 深さは**先生が決める**（英検の「きびしさ」と同じく、子どもには変えさせない）。家庭版は保護者が決める。

## 6. 1つの実験の型（すべての実験がこの形）

```
① 予想する（Predict）  → ② やってみる（Run）  → ③ 測る（Observe）
→ ④ 説明する（Explain：主張・証拠・理由）  → ⑤ クラスで比べる（Compare）
```

この流れは、米国の学習基準 NGSS の「科学・工学の実践」、PISA 2025 の科学の3つの能力、学習指導要領の「予想・仮説 → 観察・実験 → 考察」に**同時に当てはまる**（§9）。

**実験はデータで書く**（`missions.json` や `eiken.json` と同じ考え方）。1本の例：

```json
{
  "id": "cosmos.orbit.launch",
  "region": "cosmos", "spot": "launch-pad",
  "sim": "gravity2d",                       // 共有の物理モジュール（サーバーも同じものを動かす）
  "params": { "v": { "min": 3, "max": 12, "step": 0.5, "unit": "km/s" } },
  "levels": {
    "explore":     { "predict": { "choices": ["falls", "orbits", "escapes"] } },
    "investigate": { "predict": { "number": "period", "unit": "min" }, "record": ["v", "period"] },
    "engineer":    { "predict": { "number": "v_for_period", "target": 1436 }, "code": true }
  },
  "judge": { "measure": "period", "tolerance": 0.03 },   // サーバーが同じ v で再計算して比べる
  "explain": { "aims": ["speed", "gravity", "balance"], "language": "en" },
  "classPlot": { "x": "v", "y": "period" },
  "standards": { "ngss": ["MS-ESS1-2"], "jp": ["中3 地球と宇宙"], "pisa": ["explain"] },
  "real": { "kit": "ball-on-string", "note": "教室でひもとボールで遠心力を確かめる" }
}
```

- **判定はサーバー。**
  - 予想の数値は、物理で出した答えと比べる。
  - 説明（英語）は、AI が「できたこと（aims）」で判定する。英会話島とおつかい島で使っている `tutor.js` の仕組みをそのまま使う。
  - API キーが無いときは、台本モードの判定で動く。
- **答えのデータは `client/dist` に置かない**（英検の問題バンクと同じ規則）。

## 7. プログラミングは「道具」

- QUREO などの「プログラミング講座」とは**正面で戦わない**。
- ここでのプログラミングは「ローバーを動かす」「望遠鏡の観測順を組む」「ロケットの燃焼を時間で制御する」ための**手段**。
- **ブロック → 文字のコード**へ、同じ命令で上がっていける。命令は英語（`move forward 3` / `turn left` / `repeat 4` / `if rock then scan`）なので、英語の練習にもなる。
- 子どもが書いたプログラムは**サーバーで実行して判定する**（ページの申告は信じない）。
- 判定でやっていること：
  - 決まった命令だけを解釈して実行する。任意のコードは動かさない。
  - 1回に動かせる手数に上限がある。

## 8. 本物の実験とつなぐ

文部科学省の立場は「ICT は観察・実験の**代わりではなく補助**」[A25]。これに逆らわずに、**仮想と本物をつなぐ**。

- **「シムで予想 → 教室で本物 → 測った値を入れる → シムと比べる」**を、それぞれの実験の `real` に書いておく。
- 教室の道具は100円ショップで揃うものに限る（ひも・ボール・懐中電灯・磁石・ペットボトル）。
- **家でできる実験**は保護者の画面に出す。写真はアップロードさせず、**数字だけ**を入れてもらう（子どもの写真を集めない）。
- 本物の観測につなぐ：Galaxy Zoo / Planet Hunters TESS（保護者の承認つき）、その夜の月や ISS の観察。

## 9. 評価とレポート：科学の5つの力

英語の5技能レーダー（`skills.js`）と同じ形で、**科学の5つの力**を出す。

| 力 | 何を見るか | NGSS（米国） | PISA 2025 | 学習指導要領 |
|---|---|---|---|---|
| **予想する** | 予想を立てたか・根拠があるか | 問いを立てる | 科学的に探究する | 予想・仮説 |
| **はかる** | 条件をそろえて測ったか | 調査の計画と実行 | 科学的に探究する | 観察・実験 |
| **データを読む** | 表・グラフから読み取れたか | データの分析と解釈 | 科学的に解釈する | 結果の整理 |
| **説明する** | 主張・証拠・理由を言えたか（英語） | 説明の構築・証拠に基づく議論 | 現象を科学的に説明する | 考察 |
| **つくる** | モデル・コード・設計 | モデルの開発と使用・計算的思考 | 情報を評価し、意思決定に使う | 情報活用能力 |

**1つの評価軸で、日本・米国・Cambridge・IB・PISA に同時に対応する。** 対象を狭めない、の実体はここ。

**保護者レポート**（今の月次レポートにそのまま足す）には、次を載せる。

- 今月やった実験
- 科学の5つの力
- 英語で言えるようになった科学の表現
- 本物の実験・観測に参加した記録

## 10. 技術設計：作るのは「実験の層」だけ

| 必要なもの | 今あるもの（そのまま使う） |
|---|---|
| 島・建物・歩いて入る部屋 | `island-kit.js` / `island-interior.js` / `buildings.js` |
| クラス全員が同じ世界 | Colyseus の `ClassRoom`（教室あたり25〜30人で負荷試験済み） |
| サーバーと共有する物理 | `kart-drive.js` の作り（固定ステップ・決定的・共有） |
| サーバー判定・答えを渡さない | 英検・クイズ・面接の判定（`server/src/game/*`） |
| 英語の説明を AI で判定 | `server/src/ai/tutor.js`（キーが無ければ台本モード・1日の上限つき） |
| 先生コンソール・保護者レポート・CSV | `teacher.js` / `report.js` / `months.js` / `classview.js` |
| 力のレーダー | `skills.js`（形はそのまま、科学の5つの力の版を足す） |
| 英日切り替え | `i18n.js` / `i18n-dom.js`（学習の中身は訳さない仕組みつき） |
| Roblox の入口 | U-Speak Roblox |

**新しく作るもの**

1. **`sim-core`（クライアントとサーバーで共有）**
   - 重力（多体・軌道）、剛体（落下・振り子・坂）、光線、波、粒子（状態変化）、生態系（個体数）。
   - 決定的で、固定ステップで、乱数の種を持つ。
2. **実験の仕様**：`experiments/*.json` と、その読み込み・検証（`wardrobe-data.js` の `tableFrom()` のように、壊れていれば起動時に落とす）。
3. **実験の判定**：`server/src/game/lab.js`。予想・測定・コードの実行・説明（AI）。
4. **クラスのデータ**：試行を部屋で集め、散布図とヒストグラムを先生の画面と子どもの画面に配る。
5. **天文データの取り込み**：星表・月齢・光度曲線・銀河画像。**取り込むのはビルド時**にし、ライセンス表記を自動でつける。外部 API を授業中に叩かない（ISS などの位置だけは例外で、取れなければ止まらずに予測値を出す）。
6. **ブロックのコード**：決まった命令だけを解釈する小さな言語。サーバーで実行する。

**目標：実験1本を2日で作る。**

- 物理はモジュールの組み合わせ、画面は共通、仕様は JSON。
- 内容の監修（物理として正しいか）は創業者が持つ。ここが堀でもあり、ボトルネックでもある。
- だから**監修のチェックリスト**を最初に作って、監修を分けられるようにしておく。

## 12. 安全・プライバシー（世界で売るための最低ライン）

- **16歳未満は保護者の同意が前提。**
  - 日本の個人情報保護法の改正（2026年7月公布、2028年ごろ施行）が、16歳未満は法定代理人の同意を原則にした [B61]。
  - 米国は改正 COPPA の完全遵守期限が2026-04-22 [B56]。EU は国ごとに13〜16歳 [B58]。
- **チャットは今の形を保つ**：定型文が基本、先生が自由入力を切れる、NG ワード、ログが残る。
- **広告なし。位置情報はデフォルトでオフ**（英国の Children's Code）[B59]。
- **Prodigy の教訓：**
  - 学校の体験に課金を混ぜない。
  - 課金した子だけが特別に見える見た目を作らない。
  - 子どもに直接買わせる導線を作らない。
  - 課金は保護者の画面から、レポートと家庭用の実験の価値で行う。
- **サーバーが判定するので、数字が本物。** 保護者・学校・自治体に出す数字が信頼できることが、そのまま信用になる。

## 15. リスクと、この設計での手当て

| リスク（前回の調査より） | 手当て |
|---|---|
| QUREO・マイクラが強い | プログラミング講座で戦わない。**科学の中の道具**としてのコード（§7） |
| PhET などが無料 | **部品として使う**（CC BY）。こちらの価値は「歩いて入る・クラス・判定・英語・レポート」 |
| 理科コンテンツの制作費 | 実験を JSON で書く仕組みと共通の物理で、**1本2日**（§10）。段0で測って、だめなら止める |
| 文科省の「代わりではない」 | **仮想→本物→比較**を標準にする（§8） |
| Roblox への依存 | 入口だけ。売上は Web 版（§13） |
| 小さいチームで手が回らない | 段0は既存エンジンの上に COSMOS だけ。**英語版の拡販は止めない**（STEM は英語版のアドオンとして始まる） |
| 創業者の監修がボトルネック | 監修のチェックリストを作り、分野ごとの監修者（大学院生など）を足せるようにする |
| 子どもの安全・法令 | 16歳未満は保護者の同意、広告なし、定型チャット（§12） |

## 16. 決めてほしいこと

1. **段0（6週）を始めてよいか。** COSMOS の島と実験3本、`sim-core`。英語版の拡販は並行して続ける。
2. **名前。**「U-Speak STEM」のままでいくか、宇宙を前に出すか（例：U-Speak COSMOS）。英語教室向けには U-Speak の名前に乗るほうが売りやすい。
3. **ESA に Gaia の商用許諾を申請するか。** 星表は HYG（CC BY-SA）で始められるので、急がなくてもよい。
4. **ツリーベルへの実証の打診**（2〜3クラス・8週）。商談の前に確かめること：ツリーベルのプログラミング教室の今の運営・料金・英語でやっているか（前回の調査で確かめられなかった）。
