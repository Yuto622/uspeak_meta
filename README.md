# U-Speak RPG マルチプレイ版

子ども向け英語学習ワールド「U-Speak RPG」に、教室で 1 クラス（最大 25〜30 人）が同じ世界で
アバターを動かせる Colyseus ベースのマルチプレイを追加したリポジトリです。

- `client/` … 既存の 1 人用 Three.js ゲーム（`client/dist` が手書きソース）＋ マルチプレイ層 `net-*.js`
- `server/` … Colyseus 0.15 サーバー（Node 20+、プレーン JS ESM）。静的クライアントも同じプロセスで配信
- `docs/` … フェーズ0レビュー、Google Sheets 設定、実機テストのチェックリスト
- `Dockerfile` / `fly.toml` … Fly.io 東京リージョン（nrt）用

オフライン 1 人用モードはそのまま残っています（ロビーで「ひとりで遊ぶ」）。

## アーキテクチャ（要点）

| 項目 | 実装 |
|---|---|
| 同期 | クライアント 20Hz 送信（変化時のみ、無変化時は 500ms 心拍）→ サーバー 10Hz 差分ブロードキャスト（Colyseus Schema） |
| 補間 | 受信位置は 100ms 遅らせて線形補間。欠落時は最終速度で最大 250ms 外挿→静止。6 unit 超のジャンプはスナップ。定数は `client/dist/net-config.js` に集約 |
| サーバー権威 | 位置・向き・アニメは申告のまま。**正誤判定・XP・コイン・捕獲・購入・学習ログはサーバーが確定**（クライアントは「どの問題にどの選択肢を答えたか」だけ送る） |
| 判定データ | サーバーが `client/dist/*-data.js` を直接 import。データの複製なし |
| iPad 復帰 | `visibilitychange` / `pageshow` / `pagehide` / `online` を処理。復帰時に 1.2 秒以内の疎通確認→ダメなら即再接続。再接続トークン → 名前での再参加の順で復元。切断後 60 秒は席を保持 |
| 講師 | 講師キー（環境変数 `TEACHER_KEY`）をロビーで入力。判定はサーバー側のみ。全員集合／個別移動／呼び出し／チャット一時停止 |
| チャット | `client/dist/phrases.json` の定型英語フレーズのみ。サーバーも同じ JSON で ID を検証 |
| ルーム | 1 ルーム = 1 クラス（クラスコード）。`MAX_CLIENTS`（既定 30）超過は「満員」で拒否。同名は 1 席 |
| 永続化 | Google スプレッドシート（write-behind、5 秒ごと）。未設定時はローカル JSON |

## ローカル起動

必要なもの：Node.js 20 以上。

```sh
cd server
npm ci
cp ../.env.example .env         # TEACHER_KEY などを編集
npm start                       # http://localhost:2567
```

`client/dist/vendor/colyseus.js`（ブラウザ用 SDK）はコミット済みです。SDK を更新したときだけ `npm run vendor` で再生成します。

ブラウザで http://localhost:2567 を開き、アバターを選び、ロビーで名前とクラスコードを入れて参加します。
別タブ／別端末（同じ LAN なら `http://<PCのIP>:2567`）で同じクラスコードを入れると同期します。
講師として入る場合はロビーの「先生用」に `.env` の `TEACHER_KEY` を入力します。

- Google Sheets を使わない場合の保存先：`server/data/store.json`
- 開発中の自動再起動：`npm run dev`
- ヘルスチェック：`curl localhost:2567/healthz`

### 負荷テスト（25 接続・10 分）

```sh
cd server
npm run loadtest -- --url=ws://localhost:2567 --clients=25 --duration=600
# 本番: npm run loadtest -- --url=wss://<app>.fly.dev --clients=25 --duration=600 --class=loadtest
```

サーバー CPU / メモリ（`/healthz` を 5 秒ごとに取得）、1 クライアントあたりの下り帯域（KB/s）、
ブロードキャスト遅延の分布（p50/p95/p99）、切断回数を表示し、`server/loadtest-results/*.json` に保存します。

## 収容人数の目安（`docs/LOADTEST_RESULTS.md`）

| 構成 | 結果 |
|---|---|
| 1 クラス 25 人 × 10 分 | 下り 4.3 KB/s/台、遅延 p95 49 ms、CPU 2%、切断 0 |
| 4 クラス × 25 人 = 100 人同時 | 下り 4.2 KB/s/台、遅延 p95 50 ms、CPU 6%、切断 0 |
| 1 ワールドに 100 人（`MAX_CLIENTS=100`） | 下り 16 KB/s/台、遅延 p95 75 ms、CPU 5.5%、切断 0 |
| トンネル経由 1 クラス 25 人（実測） | 下り 3.8 KB/s/台、遅延 p95 182 ms、切断 0 |

クライアントは近い順に最大 32 人だけ描画し（`MAX_RENDERED_REMOTES`）、遠い人・ラベルは間引くので、
1 ワールド 100 人でも iPad 側の描画負荷は一定に抑えられます。通常授業は「1 クラス = 1 ルーム」で運用し、
学校全体のイベントで 1 ワールドにまとめたい場合だけ `MAX_CLIENTS` を上げてください。

## 環境変数

`.env.example` を参照。主なもの：

| 変数 | 既定 | 意味 |
|---|---|---|
| `PORT` | 2567 | 待受ポート |
| `MAX_CLIENTS` | 30 | 1 クラスの最大人数 |
| `TEACHER_KEY` | (空=講師無効) | 講師キー。8 文字以上 |
| `CORS_ORIGINS` | (dev: 全許可) | 許可するオリジン（カンマ区切り）。本番では必須 |
| `PATCH_RATE_MS` | 100 | ブロードキャスト間隔（10Hz） |
| `RECONNECT_GRACE_SEC` | 60 | 切断後に席を保持する秒数 |
| `STORE_BACKEND` | auto | `auto` / `sheets` / `file` / `memory` |
| `STORE_FLUSH_MS` | 5000 | Sheets への書き込み間隔 |
| `GOOGLE_SHEET_ID` ほか | | `docs/GOOGLE_SHEETS_SETUP.md` 参照 |
| `ADMIN_KEY` | (空=管理ページなし) | `/admin` の管理パスワード（12文字以上・`TEACHER_KEY` と別）。名簿の編集と制限の ON/OFF。`docs/ADMIN_ROSTER.md` |
| `ACCESS_MODE` | (未設定=管理ページのスイッチ) | `roster` で固定すると **名簿に名前がある子しか入れない**。未設定なら `/admin` のスイッチが決める |
| `ROSTER_SHEET_ID` / `ROSTER_SHEET_TAB` | (空) | 名簿を Google スプレッドシートから読む場合。`docs/ROSTER_SHEET.md` 参照 |
| `PUBLIC_SERVER_URL` | (同一ホスト) | クライアントと別ホストで動かすときの `wss://` URL（`/config.js` で配信） |
| `NET_OVERRIDES` | (なし) | クライアントの同期・描画定数を JSON で上書き（例 `{"INTERP_DELAY_MS":150,"MAX_RENDERED_REMOTES":24}`） |
| `LIVEKIT_URL` / `LIVEKIT_API_KEY` / `LIVEKIT_API_SECRET` | (空=大広間なし) | おはなし島を **100人**の通話にする SFU。未設定なら 6 人メッシュに落ちる（下記） |
| `VOICE_SFU_ALL` | `0` | `1` で **小部屋も LiveKit を通す**（LiveKit が設定されているとき）。学校の Wi-Fi で安定させたいとき |
| `ICE_SERVERS` | (空=公開 STUN) | 小部屋（メッシュ）用の TURN。`[{"urls":"turn:host:443?transport=tcp","username":"u","credential":"p"}]` の JSON |

接続先 URL はクライアントに埋め込まれていません。`/config.js`（環境変数から生成）→ `<meta name="uspeak-server">` →
`?server=` → ページと同じホスト、の順で決まります。https ページでは自動的に `wss://` になります。

## カード登録なしで実機テストする

自分の PC でサーバーを動かし、Cloudflare の無料トンネルで iPad から接続します。手順は `docs/TUNNEL_TESTING.md` を参照してください。

```powershell

winget install --id OpenJS.NodeJS.LTS -e; winget install --id Cloudflare.cloudflared -e
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

.\scripts\start-tunnel.ps1 -TeacherKey 先生用の8文字以上のパスワード
```

```sh
./scripts/start-tunnel.sh '先生用の8文字以上のパスワード'   # macOS / Linux
```

表示された `https://....trycloudflare.com` を iPad で開きます。Ctrl+C で停止し、URL は無効になります。
テスト専用で、URL は起動のたびに変わります。

### トンネルが「address does not answer」で止まるとき

cloudflared のログに `Registered tunnel connection` が出ているのに このメッセージが出た場合、
**トンネルは動いていて、確認したこちら側が失敗している**ことがほとんどです（Windows
PowerShell 5.1 が TLS 1.0 で話しかけていた／新しいホスト名がまだ引けていない）。
どちらも直したので、いまは**警告を出して そのまま動きつづけます**。表示された URL を
iPad で開いてみてください。それでも開かないときだけ、`-Protocol http2` を付け直します。

## Fly.io へのデプロイ（東京 nrt）

付属のスクリプトが、アプリ作成・`fly.toml` のアプリ名と `CORS_ORIGINS` の同期・シークレット設定・デプロイ・疎通確認までを行います。

```sh
# macOS / Linux（初回も2回目以降も同じコマンド。アプリ名は世界で一意、取られていたら別名にする）
./scripts/deploy-fly.sh uspeak-multiplayer '8文字以上の講師キー'

# Google スプレッドシートも一緒に設定する場合
export GOOGLE_SHEET_ID='<スプレッドシートID>'
export GOOGLE_SERVICE_ACCOUNT_JSON="$(base64 -w0 service-account.json)"
./scripts/deploy-fly.sh uspeak-multiplayer '8文字以上の講師キー'
```

Windows PowerShell の場合は同じ内容の `.ps1` を使います。

```powershell
.\scripts\deploy-fly.ps1 uspeak-multiplayer '8文字以上の講師キー'
```

Windows には git と flyctl が必要です。どちらも入っていなければ次で導入し、PowerShell を開き直してください。

```powershell
winget install --id Git.Git -e --source winget
powershell -Command "iwr https://fly.io/install.ps1 -useb | iex"
```

手動で行う場合は次のとおりです。

```sh
fly launch --copy-config --no-deploy --name uspeak-multiplayer --region nrt
fly secrets set TEACHER_KEY='<8文字以上の講師キー>' \
  CORS_ORIGINS='https://uspeak-multiplayer.fly.dev' \
  GOOGLE_SHEET_ID='<スプレッドシートID>' GOOGLE_SERVICE_ACCOUNT_JSON="$(base64 -w0 service-account.json)"
fly deploy
```

### 2回目からの デプロイ（`redeploy.ps1`）

アプリはもう作ってあるので、**2回目からはコードを送るだけ**です。

```powershell
.\scripts\redeploy.ps1
```

`deploy-fly.ps1`（アプリを作る・シークレットを入れる・`fly.toml` を書き換える）とは
別物で、こちらは送るだけ。そのかわり**送る前に3つ止めます**：

1. **ディスクの空き**（既定 5 GB 未満で中止）。
   2026-09 に C: の空きが 0.8 GB になったとき、`git pull` が**エラーを出さずに
   途中で切れたファイルを書き**、`fly deploy` がそれをそのまま本番へ送って
   **サイトが落ちました**。原因はデプロイの2手前にあったので、ここで止めます。
2. **コミットしていない変更**があれば中止（書きかけを送らない）。
3. デプロイのあと、**本番に実際に聞いて確かめます**
   （`/healthz` と `/lang.json` と `/i18n.js`）。「成功しました」と出ても
   壊れた中身が乗っていたことがあるので、出た数字を見てください。

Depot のビルダーが 401 を返すアカウントなので `--depot=false` を付けてあります
（昔ながらのリモートビルダーを使う。遅いが通る）。

`fly.toml` のポイント：`auto_stop_machines = false` と `min_machines_running = 1` でアイドル時にスリープしない、
`force_https = true`、`/healthz` によるヘルスチェック、`primary_region = "nrt"`。
アプリ名を変える場合は `fly.toml` の `app` と `CORS_ORIGINS` を合わせてください。

デプロイ後の確認：

```sh
curl https://uspeak-multiplayer.fly.dev/healthz
fly logs
```

クライアントを別の静的ホスティングに置く場合は、その配信元を `CORS_ORIGINS` に追加し、
`PUBLIC_SERVER_URL=wss://uspeak-multiplayer.fly.dev` を設定します（クライアント側は `/config.js` を読めない
ので、`client/dist/config.js` に `window.USPEAK_CONFIG={serverUrl:"wss://..."}` を置くか `<meta name="uspeak-server">` を使います）。

## 名簿（登録したアカウント名の子しか入れない）— 管理ページ `/admin`

**管理パスワードで `/admin` に入り、アカウント名を表に打つ・1行に1つ貼る・CSV を読みこむ**。
「名簿で制限する」を ON にすると、名簿にあるアカウント名の子しかログインできません。
必要なのはアカウント名だけ（クラスは問いません）。
判定はぜんぶサーバー側（`ClassRoom.onAuth`）で、名簿はブラウザーに渡りません。手順は `docs/ADMIN_ROSTER.md`。

```sh
fly secrets set --app uspeak-multiplayer ADMIN_KEY='<12文字以上の管理パスワード>'
# → https://uspeak-multiplayer.fly.dev/admin
```

- 名簿はアカウント名の1列。CSV は 1 行に 1 つ（1行目が `name` / `アカウント名` なら見出し）。Google スプレッドシート・Excel の「CSV でダウンロード」がそのまま読める（Shift_JIS も可）。「⬇ CSV で保存」で取り出せる。
- **保存するとその場で効く**（授業中に足した子もすぐ入れる）。名簿にない名前は、前に遊んだことがあっても入れない。`TEACHER_KEY` を持つ先生は名簿を見ずに入れる。
- 名簿は `data/roster.json`、スイッチは `data/roster-settings.json`（Fly のボリューム）。環境変数 `ACCESS_MODE` を設定するとそちらが優先される。
- 効いたかは `/healthz` の `"gate":{"mode":"roster",...,"admin":true}` で分かる。
- ログインは 12 時間・HttpOnly Cookie、入力ミス 8 回で一時ロック、書きこみはページ自身のスクリプトからだけ。

### Google スプレッドシートを名簿にする場合


Google スプレッドシートを名簿にして、そこに書いてある **アカウント名の子だけ** が
ログインできるようにできます。先生はシートに名前を足す・消すだけ。判定はぜんぶサーバー側
（`ClassRoom.onAuth`）で、名簿はブラウザーに渡りません。手順は `docs/ROSTER_SHEET.md`。

```sh
fly secrets set --app uspeak-multiplayer ACCESS_MODE=roster \
  ROSTER_SHEET_ID='<スプレッドシートID>' \
  GOOGLE_SERVICE_ACCOUNT_JSON="$(base64 -w0 service-account.json)"
```

- シートは `class | name | note` の3列（見出しは `クラス | 名前 | メモ` でも可）。`class` が空か `*` の行は
  どのクラスでも入れる名前。`name` 1列だけのシートでもよい。
- サービスアカウントのメールアドレスにシートを **閲覧者** で共有する（サーバーは読むだけ）。
  学習記録をすでに Google シートに置いているなら同じサービスアカウントで足りる。
- 名簿にない名前は、前に遊んだことがあっても入れない。`TEACHER_KEY` を持つ先生は名簿を見ずに入れる。
- シートが一時的に読めないときは **最後に読めた名簿** で判定する（授業中に Google が落ちても締め出さない）。
- 効いたかは `/healthz` の `"gate":{"mode":"roster","register":"google-sheet"}` で分かる。
  手元で `cd server && node scripts/check-roster.mjs 6-1` と打つと、サーバーと同じ目でシートを読んで
  入れる名前を並べる。
- 授業中に足した名前は 5 分で反映。すぐ入れたいときは先生コンソールの「🔄 めいぼを読み直す」。
- **鍵の JSON をチャットやメールに貼らないこと。** `fly secrets set` に直接入れる。

## 英検の島の「めんせつの間」（二次試験の練習）

5級・4級・3級の島それぞれに、**5つめの建物**が建ちました。島のいちばん奥、正面に見える
小さな建物です。中に入って **E** を押すと、ウーピーが面接官として座っています。

**本番と同じ順番**で進みます：

| | 5級・4級 | 3級 |
|---|---|---|
| ① 音読 | パッセージを 声に出して 読む | 同じ |
| ② パッセージの質問 | 1問 | 1問 |
| ③ イラストの質問 | 4級のみ 1問 | 2問 |
| ④ 自分のことの質問 | 1〜2問 | 2問（最後は「もっと話して」） |

- **マイクで答えます**（書いてもOK）。送るのは聞き取った文字列だけで、
  **採点はすべてサーバー**（`server/src/game/interview.js`）。お手本の答えは
  **答えたあとにしか出ません**。
- **まちがえても最後まで進みます。** 本番の面接がそうだからです。終わると
  「3 / 4」のような結果カードと、次に練習することが出ます。
- **コインは完走したときだけ**（30🪙・級が上がるほど増える。英検の島の1日の上限と共通）。
- **AIキーが無くても動きます。** 質問と質問のあいだのことばは台本で、
  最後の講評だけ AI が書きます（キーが無ければ台本の講評）。面接1回で AI は1回しか呼びません。

## 英検の「はんていの きびしさ」（先生が3段階で決める）

先生コンソールの **`📝 英検：…`** を押すと、きびしい → ふつう → やさしい と まわります。
クラス全員に同じものが効きます。

| | 話す・面接 | 書く（ならべかえ） | 読む・聞く（4たく） |
|---|---|---|---|
| **きびしい** | 1語も ちがえられない | お手本と 完全に 同じ順 | 4たく・ことばの ヒントなし |
| **ふつう**（はじめはこれ） | 5語に1語まで | お手本と 完全に 同じ順 | 4たく・ヒントあり |
| **やさしい** | **言いかえを 同じ意味としてから** 4語に1語まで | となりどうしの 入れかえ 1か所まで | **2たく**・ヒントあり |

**やさしいで通るようになる言いかたの例**（`I would like ...` を `I want ...` と言った子）：

| お手本 | 言ってもよくなる |
|---|---|
| I **would like** a hamburger. | I **want** a hamburger. |
| **May I** have some water? | **Can I** have some water? |
| **Could you** help me? | **Can you** help me? |
| **I am** from Japan. | **I'm** from Japan. |
| I am **going to** play soccer. | I am **gonna** play soccer. |

- **決められるのは先生だけです。** 子どもが自分で「やさしい」にしてコインを取ることは
  できません（画面には出ますが、押せるのは先生コンソールだけ）。
- **やさしいでも「言えていない」は通りません。** 答えが空、ぜんぜんちがう文、
  **打ち消しの有無がちがう文**（`I like apples.` に `I don't like apples.`）は ×。
- **いま解いている5問の採点は、途中で変えても動きません。** 変わるのは次のセットから。
  画面の右上に「はんてい：やさしい」と出ているので、子どもにも先生にも見えます。
- **学習ログにも残ります**（`eiken:g5:speaking:easy:3`）。保護者レポートで
  「やさしい判定での満点」と「きびしい判定での満点」が同じに見えないようにするためです。
- 面接（めんせつの間）の音読も、同じ きびしさで採点します。

## 同梱した外部のゲーム（AURORA KART / BLOCKWILD）

島のパネルから、まったく別に作られたゲームが画面いっぱいに開きます。どちらも**1バイトも
改変せずに同梱**していて（`client/dist/racers/` と `client/dist/blockwild/`）、three.js の
バージョンがこの世界と違うため iframe で隔離して動かしています。帰るときは、そのゲームの
メニューにある **「← U-Speak」**。

**入口は2つあります。** 島の中の扉（ガレージのカード／ブロックの とびら）と、
**島に降りた時点で画面の左下に出るボタン**（`guest-dock.js`）。
のりもの島とまちづくり島だけに出て、建物の中に入ると引っ込みます。
扉は「歩いていて見つける」ため、左下のボタンは「初めて来た子に、あることを知らせる」ため。

### AURORA KART（のりもの島）

のりもの島に降りると、**左下に「🏁 AURORA KART」のボタン**が出ます。
**スタートライン**で E を押しても、2つのレースから選べます。

| | |
|---|---|
| 🚦 **クラスの レースに でる** | この島のコースを3周。みんなと順位を争う（U-SPEAK GRAND PRIX） |
| 🕹 **AURORA KART** | まったく別のカートゲームが画面いっぱいに開く |

各ゲート（キックボード置き場など）のガレージからも同じように開けます。

4コース／4マシン／7人のライバル、グランプリ・タイムアタック・**英単語モード**
（英検5〜3級・326語）。

### ミニゲーム島（あたらしい島）

ワールドマップから **ミニゲーム島** に飛ぶと、家がふたつ立っています。
**入った家が、そのままゲーム**です（押す必要はありません。戸口に入った瞬間に開きます）。

| 家 | ゲーム |
|---|---|
| 🟣 **PUYO U-SPEAK** | ぷよぷよ。ぷよに1文字ずつ入っていて、**英単語を綴ると消える**。クラシック／VS COM もあり |
| 🍉 **えいご スイカゲーム** | スイカゲーム。同じものが合わさると進化して、**英単語カードが出る**。20ジャンル220語 |

どちらも通信を一切しないので、**オフラインでも遊べます**。

### BLOCKWILD（まちづくり島）

まちづくり島に降りると **左下に「⛏ BLOCKWILD」のボタン**が出ます。
島の北東にある **⛏ ブロックの とびら** に**歩いて入って**も開きます（押す必要はありません。
他の建物と同じで、戸口に入った瞬間です）。森と山と湖でできた島をひとつ生成して、掘って、
灯をともして、積み上げるサンドボックス。クリエイティブとサバイバルの2モード。

**ブロック屋とつながっています。** クリエイティブで使えるのは、まちづくり島の
**ブロック屋で U-Speak コインを払って買ったブロックだけ**です。

```
英語をやる → コインが貯まる → ブロック屋で買う → BLOCKWILD で建てられる
```

- 何も買っていない子は **「き」ひとつ**（ブロック屋で 0 コイン）から始まります。
- 買った持ち物はサーバーが持っています。ブロック屋の棚は**そのブロックを立体で**表示します。
- **サバイバルは従来どおり**です（掘って手に入れるモードなので、掘ったものまで
  取り上げるとゲームが成立しません）。ブロック屋が受け持つのはクリエイティブです。

### 出てきた戸口では、もう一度開きません

**戸口を歩いて入ると開く作りなので、別ゲームから帰ってきた子が立っているのは必ずその戸口です。**
以前は「出た直後の1.4秒だけ待つ」で止めていましたが、**その時計は別ゲームが開いている間
ごと止まっています**（島の描画をまるごと止めているため）。そのため戻って1.4秒後に、
指一本ふれていないのに同じゲームがまた開いていました。

いまは**時間ではなく場所**で止めています。開けた戸口を覚えておき、**そこから歩いて
離れるまで**二度目は開きません。離れて入り直せば、いつもどおり開きます。
パネルのカード（AURORA KART）や左下のボタンから開いたときも同じです。

### BLOCKWILD は クラスで いっしょに（20 人まで／2026-10 追加）

**クラスに入ってから BLOCKWILD を開くと、そのクラスの「みんなの世界」に自動で入ります。**
名前もつなぎ先も入れ済みで、押すものはありません。同じクラスの子は同じ地形（同じシード）に立ち、
誰かが置いた・掘ったブロックは **その場で全員に届き**、あとから入った子にも最初に全部渡ります。
友だちの姿と名前が見え、ベッドで寝れば全員の朝になります。**いちどに 20 人まで**。21 人目には「満員」。

- サーバーは `server/src/blockwild/server.js`。同梱ゲームは **1 バイトも触っていません**：あちらが元から持っている
  マルチの通信（`blockwild/src/net.js`、JSON ＋ 差分 1 本のバイナリ）に、こちらが「相手側」を書いただけです。
  同じポートで、`/bw/<クラス>/ws` と `/ws` だけをこちらが受け、それ以外の WebSocket は今までどおり Colyseus へ。
- 世界は **クラスごとに 1 つ**。シード・時刻・天気・編集したブロックの一覧を `DATA_DIR/blockwild/<クラス>.json`
  に保存します（Fly では `uspeak_data` ボリューム）。再起動しても、作ったものはそのままです。
- スポーン地点は、同梱の地形生成をサーバーの worker で 1 回だけ回して決めます（約 1 秒・世界を作る時だけ）。
- 生き物はオンラインの世界には出ません（サーバーが生き物を持たないため）。作る・掘る・歩く・話すが主役です。
- **コインも学習記録も動きません。** ブロック屋の持ち物の制限（クリエイティブ）はこれまでどおり。
- クラスに入っていない（オフライン）ときは、今までどおり 1 人の世界です。
- 検査：`server/test/blockwild.test.mjs`（6 項目・2 人で同じ世界・ブロックが届く・あとから入った子に差分・
  21 人目は満員・不正な値は捨てる・再起動しても残る・Colyseus と同居）/ `server/test/e2e/browser-blockwild.mjs`
  （実ブラウザ 2 画面・自動で入る・相手が見える・置いたブロックが向こうに出る）。

### 共通の注意

- **AURORA KART のオンラインのタブは外してあります。** あちらの通信は WebSocket をこのサーバーの**ルート**に
  つなぎに行き、そこは教室の Colyseus の口だからです。みんなで走るのは **U-SPEAK GRAND PRIX**（スタートライン）。
  BLOCKWILD は上のとおり、クラスの世界につながります。
- **コイン・学習記録はこちらに入りません。** AURORA KART は正解の判定をブラウザ側で
  していて（語彙データがクライアントにあります）、そこから出た数字を保護者向けの
  記録に混ぜないためです。成績はそれぞれのゲーム側に別で貯まります。
- 開いている間、後ろの島は描画を止めます。閉じるとフレームごと破棄します。

差し替えるときはフォルダごと置き換えて
`node client/tests/guests-manifest.mjs --write <racers|blockwild>` を実行してください
（回帰テストがハッシュを照合します）。

## ぼくじょう島（牧場物語 × 英語／2026-10 追加）

**牧場の一手一手が、英語の一言。** 牧場物語は道具を振るたびに体力が減る。ぼくじょう島は
作業をするたびに英語を一つ出す。正解すれば作業が進み、まちがえれば進まない（種もコインも減らない）。
リサーチは `docs/uspeak-farm-research.md`、設計は `docs/uspeak-farm-island.md`。

| 建物 | やること | 英語（**英検5級・小1でも読める**） |
|---|---|---|
| 🌱 たねや（Hana） | 季節の種・ニワトリ/ヒツジ/ウシ・ジョウロを買う | **3 枚のカードを並べる**（Two carrots, please. / A chicken, please.） |
| 🌿 ビニールハウス（Gramps） | 9 マスの畑：植える・水やり・収穫・片づけ | 植える＝**絵を見て英単語を選ぶ**／水やり＝**絵つきの穴うめ**（This is an ___. → apple）／収穫＝How many? |
| 🐄 どうぶつ小屋（Taro） | エサ・**みず**・ブラシ・卵/牛乳/羊毛をとる | エサ＝**鳴き声**（Cluck / Baa / Moo）／みず＝絵つきの穴うめ／ブラシ＝動物の名前／とる＝egg / milk / wool |
| 📦 しゅっか小屋（Zack） | 出荷してコインに、クラスの収穫祭の掲示板 | 品名を**つづる**：短い語は**文字タイルを並べる**、長い語は 3 つのつづりから選ぶ |
| 🍳 だいどころ（Mia） | レシピで料理（売値 2 倍、贈り物に） | **なにが入っている？**（材料の英単語を選ぶ） |

- **問題は全部 1 問 1 画面・絵つき・日本語つき。** 問題バンク `server/src/game/farm-bank.json` は英検5級の語だけ
  （色・数・食べ物・動物・家族・あいさつ）。答えは 1 語か 3〜4 語の決まり文句で、長い文は作っていない。
  以前の「I'd like three turnip seeds, please.」「First / Then / Finally」は小1には読めなかったので捨てた。
- **畑と柵は歩いて入る**（2026-10）。「ビニールハウスの中の 2D の畑では臨場感がない」と戻ってきたので、
  **はたけの マスの上に立って E** で その場のカードが開く（あいていれば たねを えらぶ／かわいていれば
  すぐ みずやりの問題／できていれば しゅうかく）。正解すると足もとのマスが はねて芽が出る。柵の中に入れば
  どうぶつの せわ。サーバーは `FARM.placeById` の `field` / `pen` で**その場に立っているか**を建物と同じに確認する
  （`SPOT_OF_ACT` は `['field','house']` のように 2 か所を許す）。ビニールハウスは 9 マスの一覧として残してある。
- **「つぎ」の帯が画面のいちばん上にある**（`client/dist/farm.js` の `nextStep()`）。「たねやで たねを かう」→
  「ハウスで うえる」→「みずを やる」→「どうぶつ小屋で えさ」→「しゅっか小屋で うる」の順に、いま何を
  すればいいかを 1 行で出し、**屋外ではその建物に光の柱が立つ**（`island.setTarget`）。各画面の下には
  ①②③ の 3 コマの手順。問題は 🔊 で読み上げ、正解・不正解も声で返す。
- **E キーでも開く。** `game.js` の E キーの連鎖に `farmNearby` が入っていなかった（クリックの連鎖にだけ
  あった）ので、建物の中で E を押しても何も起きなかった。直した。
- **1 日＝世界時計の 1 周（約 12 分）。** 水やりは 1 日 1 回。カブ（2 回）は授業 1 回で収穫できる。
  **季節＝本物の季節**で、店に並ぶ種が変わり、季節が変わると畑の作物は枯れる（片づけるのも英語）。
  検査で日を縮めたいときは `FARM_DAY_SEC`。
- **どの建物でも住人と話せる**（1 日 1 回・受け答えを選ぶ：Hello! → Hello! / How are you? → I'm fine, thank you.）。
  贈り物は「This is for you.」を並べる。ハートが店の品ぞろえ・動物・レシピを解放する。好物は `farm.json` の `likes`。
- **コインが増えるのは出荷だけ**（1 日 `dailyCoinCap`＝150 まで）。XP は正解ごと。学習ログの mode は
  `farm-word / farm-fill / farm-order / farm-spell / farm-letters / farm-reply` で、5 技能に振り分けられる。
- **答えはブラウザーに来ない。** 問題文・選択肢・並べるカードだけ（`farm:ask`）。判定は `farm:answer` でサーバー。
  問題バンクは `server/src/game/farm-bank.json`（`client/dist` には置かない）。作物・値段・成長日数は
  `client/dist/farm.json` をページとサーバーが同じく読む。買い物の請求は効果の `spend` が名指しする
  （これが抜けると店がタダになる — `farm.test.mjs` が見ている）。
- **4 季は牧場の暦（2026-10）。** 本物の季節だと子どもは 1 学期に 1 季節しか見ないので、**1 季節 = 7 牧場日**（`FARM_SEASON_DAYS`、
  約 80 分）で 春→夏→秋→冬 と回る（`calendarOf()`：`season` / `seasonDay` / `left` / `year`）。店の種・畑の枯れは この暦に従い、
  画面の季節の帯が「はる 3日め / 7日・あと 4日で なつ」と出す。種のカードは その季節に間に合わないと「⏳ まにあわないかも」。
- **季節ごとの おまつり。** `farm.json` の `events`（おはなみ 🌸 Hana／なつまつり 🍉 Zack／しゅうかくさい 🎃 Gramps／ゆきまつり ⛄ Mia、
  各季節の 3〜5 日め）。その日は島に提灯と屋台が出て、ホストの家で `event` の act（おまつりの受け答え・`farm-bank.json` の `festival`）。
  正解で **ホスト ❤+2・ほかの住人 ❤+1・ごほうび 40 コイン**（`prize`：出荷の日上限の外）。年に 1 回（`farm.events[id] = year`）。
  おまつりの期間は `wants` の品が **出荷 1.5 倍**、ホストへの贈り物なら **❤+3**。検査は `FARM_FESTIVAL_DAYS=all` で毎日おまつり。
- **住人との親密度は上下する。** 話す ❤+1、贈り物 ❤+1（すき ❤+2・きらい 💔−1、`farm.json` の `likes` / `dislikes`、カードに表示）、
  **誕生日**（各住人に `birthday`）は話すと「Happy birthday!」で ❤+2、プレゼントは 2 倍。**30 牧場日 話さないと ❤−1**（`FORGET_DAYS`、
  `settle()` が 1 回だけ引く）。ハートの段階は しりあい(0–2)・ともだち(3–5)・なかよし(6–9)・しんゆう(10)（`friendship()`）。
- **雨が降る。みずやりは義務（2026-10）。** 牧場日ごとに決定的に晴れか雨かが決まる（`farm.js` の `rainyDay(day)`、
  ハッシュなので**クラス全員が同じ日に雨**。割合は `FARM_RAIN_PCT`、既定 30%）。**雨の日は 畑のマス全部に水がやられて育ち、
  家畜の水おけも全部いっぱいになる** — 子どもは何もしなくていい。晴れの日に水をやらないマスは **`DRY_DAYS`＝3 日で枯れる**
  （`settle()` が最後に見た日から今日まで 1 日ずつ再生して、雨の日は水やり・乾いた日は枯れ判定をする。初回だけは枯らさない）。
  家畜は **エサと みずの両方**がその日に済むまで卵・牛乳・羊毛をくれない（`thirsty`）。みずは `trough` の act（絵つき穴うめ）。
  雨の日に水おけを押すと `rain did it`。`farm:state` に `weather` / `rainIn`（次の雨まで何日）/ `dryDays` が乗り、
  画面の天気の帯（`#farm-weather`）と「つぎ」の帯が雨の日は水やりを飛ばす。島には雨粒（`setWeather`）が降る。
  検査サーバーは `FARM_RAIN_PCT=0` で晴れに固定（`room.test.mjs` / `browser-farm.mjs`）。
- **家畜は 3D。** `farm-animals.js` の `buildAnimal(kind, {hearts, seed})` が ニワトリ・ヒツジ・ウシを箱と球で作り、
  柵の中（うろうろ歩く）と、たねやのカード・さくのカードの写真（`farm-preview.js` が 1 つの描画器で焼く）と、
  さくの上の**回る牧草地**（指で回せる）が同じモデル。WebGL が無ければ絵文字のまま。
- **屋外に自分の畑と動物が見える。** 芽→葉→実の 3 段階、動物は買った分だけ柵の中に。サーバーの状態からだけ描く。
- 保存は `farm_json` 1 列（`farm_coins` は 1 日の上限）。
- **あそびかたガイド（?）に 16 ページ**（島・たねや・こたえあわせ・はたけ・どうぶつの さく・あめの 日・きせつ 4 ページ・おまつりの 日・
  おまつりに さんか・おまつりの もんだい・住人と なかよく・しゅっか小屋・だいどころ）。きせつと おまつりの写真は
  `server/test/e2e/capture-farm-seasons.mjs` が撮る（4 季はページの `onState` に暦を差し替えて見せる。島は言われたものしか描かないので、それで本物と同じ絵になる）。
  写真は `browser-farm.mjs` が撮る `docs/figures/screen-farm-*.jpg` から。

## 英会話島（AI英会話・キャラクター動画）

ワールドマップから **英会話島** に飛ぶと、4つの家があります。家に入って E を押すと、
ウーピー（画面の中のキャラクター）と英語で会話できます。

| 家 | 場面 | レベル |
|---|---|---|
| であいのカフェ | はじめまして／カフェでたのむ | 英検5級 |
| おかいものストリート | おみせでかう／みちをきく | 英検5級 |
| がっこうテラス | 学校の一日／しゅうまつのこと | 英検4級 |
| ゆめのとうだい | しょうらいのゆめ／行ってみたい国 | 英検3級 |

- **話すのはマイク、書いてもOK。** 送るのは「マイクが聞き取った文字列（または入力した文）」だけで、
  できたかどうかの判定は**すべてサーバー**（`server/src/ai/tutor.js`）。
- **できたこと（2〜3個）** が1つ埋まるごとに XP、全部そろうと **+40🪙**（1日の上限200）。
- **`OPENAI_API_KEY` が無くても動きます**（台本モードのウーピーが相手をします）。
  本物の会話にする手順は次の節。

### AI英会話を オンにする

**スイッチは `OPENAI_API_KEY` ひとつだけ**です。入っていれば本物の AI、入っていなければ
台本のウーピー。コードは同じで、`server/src/ai/tutor.js` が起動時にどちらか選びます。

```powershell
fly secrets set --app uspeak-multiplayer OPENAI_API_KEY='sk-...'
```

`fly secrets set` は**そのままマシンを入れ替えます**（`fly deploy` は要りません）。
1〜2分で戻ってきます。

**効いたかどうかは `/healthz` で分かります**（`fly logs` を読まなくてよいように出しています）：

```powershell
curl.exe -s https://uspeak-multiplayer.fly.dev/healthz
```

- `"ai":{"provider":"openai","model":"gpt-4o-mini",...}` … **オン**
- `"ai":{"provider":"scripted","model":"",...}` … まだ台本モード

出るのは**「鍵が入っているか」だけ**で、鍵そのものもその一部も出しません
（ブラウザーには昔から何も渡していません）。

**使う量の上限も同時に決められます**（1人1日のやりとり回数。おつかい島と合算）：

```powershell
fly secrets set --app uspeak-multiplayer AI_DAILY_TURNS_PER_STUDENT=40
```

既定は 200 で、これは**多すぎます**。生徒1人が1日200往復すると
`gpt-4o-mini` でもそれなりの額になり、月200円の価格では合いません。
**40 なら1レッスンぶんとして十分**で、上限に達した子には台本のウーピーが出ます
（授業は止まりません）。ほかに `OPENAI_MODEL`（既定 `gpt-4o-mini`）、
`AI_MAX_TOKENS`（300）、`AI_MIN_INTERVAL_MS`（1200）も同じやり方で変えられます。

**鍵は絶対にリポジトリに入れないこと。** `fly secrets` はサーバーの中だけに置かれ、
`fly.toml` にも git にも残りません。**画面に一度でも貼ってしまった鍵は捨てて、
新しいものを作ってください**（OpenAI のダッシュボードで revoke → 新規発行）。
- キャラクターは `client/dist/assets/character/idle.mp4` と `talking.mp4` の2本だけ。
  読み上げが鳴っている間だけ talking に切り替わります。差し替えるときは
  **同じ構図・同じ照明・最初と最後のフレームを揃える**（クロスフェードが見えなくなります）。
  デコードできない端末では絵のフクロウに自動で落ちるので、会話は止まりません。

## メッセージ（定型文と じゆうにゅうりょく）

**どの島にいても、通話に入らなくても書けます。** 画面右下の 💬 がクラス全員のチャット、
建物の中では通話パネルにもう一つ入力欄が出て、そちらは**その部屋の人にだけ**届きます。

- **定型文（`phrases.json`）と、自分のことば**の両方。定型文はタップすると読み上げもします。
- **XPが出るのは定型文だけです。** 書いた文にXPを付けると「XPのために書く」ようになるので付けていません。
- **通す・通さないはサーバーが決めます**（`server/src/game/say.js`）。
  120文字まで／同じ文の連投・同じ文字の連打はねる／**電話番号・URL・メールアドレスは送れない**／
  傷つくことば（`server/src/game/ng-words.json`）は届かない。止まった理由は子どもの画面に日本語で出ます。
- **先生の手当ては3つ**：`✏ じゆうにゅうりょく` をオフにすると**定型文だけ**に戻る／
  `⏸ チャットを一時停止` は両方止める／**書いた文も、止められた文も学習ログに残る**ので、
  あとから先生が確認できます（保護者レポートには出ません）。
- ことばの一覧は学校ごとに足してください（`ng-words.json`。サーバーだけが読みます）。
  **単語リストは柵であって見張りではありません。** 先生のスイッチとログのほうが本体です。

## おはなし（通話）と大広間（100人）

部屋に入ればその部屋の全員と話せます。**部屋の大きさで仕組みが変わります。**

| | どこ | 人数 | 仕組み | サーバー費用 |
|---|---|---|---|---|
| 小部屋 | どの島の建物の中でも | 6人 | ブラウザー同士の直結（WebRTC メッシュ） | なし |
| 大広間 | おはなし島のひろば | **100人** | SFU（LiveKit）が声を1本ずつ受けて配る | LiveKit が要る |

**大広間には LiveKit が要ります。**3つの環境変数を入れるだけで、クライアントの変更は不要です。
未設定でもサーバーは普通に動き、おはなし島は 6 人メッシュに落ちて、画面にもそう出ます。

```bash
# 1) LiveKit Cloud（無料枠あり・東京リージョンを選べる）: https://cloud.livekit.io
#    プロジェクトを作って URL / API Key / API Secret をコピーする
fly secrets set LIVEKIT_URL=wss://<your>.livekit.cloud LIVEKIT_API_KEY=... LIVEKIT_API_SECRET=...

# 2) 自前で建てる（バイナリ1つ。Docker は不要。1.10 以降が必要）
curl -sSL https://get.livekit.io | bash
livekit-server --keys "mykey: <32文字以上の秘密>" --node-ip <サーバーの公開IP>
#    UDP 50000-60000 を開ける。学校が UDP を塞いでいる場合は --rtc.port-tcp 7881 で TCP にも出せる
```

鍵はサーバーから出ません。ブラウザーに渡るのは **その子・その部屋・2時間・何を出してよいか**を
書いて署名したトークンだけで、`server/src/game/stage.js` が発行します。

- **声は全員、カメラは先生と「ステージ」の子だけ。** 100台のカメラは授業ではなく通信障害なので、
  先生コンソールの名簿の 🎙 ボタンで子どもをステージに上げると、その子だけカメラと画面共有が開きます。
- **メッセージ（定型文）は人数に関係なく使えます。** マイクを入れていなくても読み書きできます。
- 動作確認：`LIVEKIT_BIN=./livekit-server node server/test/e2e/browser-stage.mjs`
  （本物の LiveKit を起動して実ブラウザー3枚で通す。バイナリが無ければ SKIP）。

### 通話を快適に（2026-10 更新：雑音・全画面・大きさ・つながりやすさ）

教室から「雑音が混ざる」「画面が小さい」「隅から動かせない」と戻ってきたので、通話の体験を
Google Meet に寄せました。**仕組み（メッシュ＋LiveKit）は変えず、足りなかった 4 つを足しています。**

| 困りごと | 直したこと | どこ |
|---|---|---|
| 雑音が混ざる | ① ブラウザーのエコー消し・ノイズ抑制・自動ゲイン・音声分離を全部要求（モノラル・48kHz）。② **送る前に音を掃除**：ハイパス（110Hz）→ ローパス（7.6kHz）→ **言葉の合間に閉じるゲート**→ 軽いコンプレッサー（`voice.js` の `cleanMic()`、ブラウザーの AudioContext だけ・約10ms）。③ **通話中は島の BGM を 18% に下げる**（スピーカーから出た曲をマイクが拾って相手に届いていた）。 | `voice.js` / `ambience.js setDucked()` |
| 全画面にしたい | **⛶ ぜんがめん**：顔が人数に合わせたグリッド（1→1、4→2×2、9→3×3）で画面いっぱい、右にメッセージ、下にボタン。対応ブラウザーでは本当の全画面（アドレスバーも消える）。**全画面中は WASD で歩かない**（うっかり部屋を出て切れないように）。Esc か「もどす」で戻る。 | `voice.js setFull()` / `voice.css` |
| 大きさを自在に | 小→中→大→特大のボタンはそのまま。くわえて**ヘッダーをつかんで動かす・右下の角をつまんで伸ばす**。位置と大きさは `localStorage` に残る（`uspeak-voice-box-v1`）。顔をタップすると**その人を大きく**（ピン留め）、もう一度で元に戻る。話している人は緑のふちどり。**🚪 おわる** で部屋を出ずに切れる。 | `voice.js`（`grab()`） |
| つながらない・途切れる | **送る量を人数で決める**（2人まで 900kbps、4人まで 500、それ以上 300、声は常に最優先）。学校のネットワークが UDP を塞いでいるときのために **TURN を `ICE_SERVERS` で渡せる**（部屋に入るときに `voice:room` で配る。ページには埋め込まない）。さらに **`VOICE_SFU_ALL=1` で小部屋も LiveKit を通す**：1 本の上りで済み、パケットロスに強く、TCP/443 にも逃げられる。 | `voice.js tuneSenders()` / `config.js` / `ClassRoom.voiceKindOf()` |

- **ノイズカットは切れます**（🧹 ボタン・通話中でも即時）。歌の授業のように、静かな余韻が要るとき。
  選択は `uspeak-voice-clean-v1` に残ります。
- **API の見直しについて。** いまの構成（6 人まではブラウザー直結、それ以上は LiveKit）は費用と品質の
  バランスでは妥当で、Meet 並みの安定を学校で出すために足りないのは**コードではなくインフラ**です：
  (1) LiveKit を設定して `VOICE_SFU_ALL=1`（Meet も Zoom も SFU です）、(2) UDP が塞がれた学校のために
  TURN（`ICE_SERVERS`、LiveKit Cloud なら不要）。Daily / Twilio / Agora のような SaaS に乗り換えても
  やることは同じで、分課金が増えるだけなので、この版では乗り換えていません。
- **夜の暗さ**も同じ回で直しました：子どものアバターが**暖かい光**を持って歩きます（`atmosphere.js` の
  `lamp`、夜だけ点く）。夜の底の明るさ（半球光・太陽・露出）も少し上げました。
- 検査：`server/test/e2e/browser-voice.mjs`（実ブラウザー 2 枚。送っている音声トラックが掃除後のものか、
  BGM が下がるか、⛶ が画面いっぱいか、ピン留め、つまんで伸ばす、🚪 で切れるか）。

## 保護者レポートの「今月のまとめ」

レポートのいちばん上に、**その月にやったこと**が出ます。累計（レベル・ためた XP・
正解率）はその下。

| | |
|---|---|
| きた日 | その月に実際に問題を解いた日数 |
| といた問題 | 正解 / 挑戦 |
| 正解率 | やっていない月は 0% ではなく「—」 |
| 学習した時間 | 直近2分以内に動いたか答えた子だけ積む（開きっぱなしは数えない） |

その下に**直近5か月**が並びます。**累計だけでは、3年つづけた子と3年前に3か月だけ
やった子が同じ数字に見えます。** 保護者が毎月受け取って意味があるのは今月のほうで、
これは累計から引き算できません（去年の分が混ざるため）。

- **レポートのリンクに期限はありません**（署名はクラス名と名前だけ）。先生が一度
  配れば、そのまま毎月の連絡に使えます。新しくリンクを配り直す必要はありません。
- **月の区切りは日本時間。** サーバーは UTC で動くので、そのまま切ると
  **1日の0時〜9時のレッスンが前の月に落ちます**。8月1日の朝のレッスンが「7月」に
  数えられると、保護者の手元の数字と教室の出席簿が合わなくなります。
- **持つのは13か月ぶん。** 4月に「去年の4月」と並べられるようにするためです。
  古い月から自動で落ちます。
- **数え方は「答えた瞬間に1つ足す」**（`server/src/game/months.js`）。学習ログは
  追記専用で読み返せないので、月末に数え直すことができません。11か所ある学習ログの
  書き込みが全部通る `appendLearning()` の中で足しているので、12個目の活動を足した人が
  この仕組みを知らなくても数えられます。
- **時間を数えはじめる前の月は 0 分**です。ぜんぶ 0 の列は表から消えます
  （「先月は1分もやっていない」と読めてしまうため）。
- 検査は `server/test/months.test.mjs`（7項目・**日本時間の境目**、壊れた保存、
  古い月の落とし方、やっていない月の正答率）。

### 生徒も自分で見られます（マイページ）

同じ「今月のまとめ」が、生徒のマイページ（ヘッダーのコインをタップ）にも出ます。
累計の3つのカードより**上に、濃い色で**置いてあります。

**累計は増えるいっぽうで、毎日見てもほとんど動きません。今月は毎月0から始まります。**
「今日やれば今日増える」が見えるのはこちらで、7歳にはそれがぜんぶです。
先月と比べた一言（「先月より 2日 おおい」）も添えます。**減っていても出します** ——
増えた月だけ褒めると、その月しか見なくなるためです。

**数字は保護者レポートとまったく同じもの**（サーバーの同じ `recentMonths()` から
出しています）。家で保護者が見た紙と、教室で本人が見る画面が食い違いません。

## 年度をまたぐ（クラスが変わっても記録を続ける）

記録は **`クラスコード｜なまえ`** で引いています。つまり **4月にクラス名を変えると、
その子は0から始まります。** 3年つづけた子の3年分が消えるのは、このサービスがいちばん
失ってはいけないものなので、引き継ぐ道を用意しました。

先生は**新しいクラスに入った状態で**、前のクラス名を指定します（先生コンソールから
`carryover`）。

```
{ cmd: 'carryover', from: '2026', names: ['さくら', 'けん'] }
```

- **上書きはしません。** 新しいクラスで既に遊んでいる子は飛ばします（どちらの記録が
  正しいかを機械が決めてはいけないため）。飛ばした子と理由は先生に返ります。
- **前の記録は消しません。** やり直せるようにしてあります。
- **去年配ったレポートのリンクが、そのまま動きます。** 署名にクラス名が入っているので
  リンクは発行し直せません。前の記録に「引っ越し先」を書いておき、`/report` がそれを
  追って新しい記録を見せます。**保護者に配った紙を配り直さなくて済みます。**
- いま接続している子は飛ばします（置いたそばから上書きされるため）。降りてから。

## クラスの記録を持ち出す（CSV）

先生コンソールの `📄 保護者レポートのリンク` を押すと、一覧のいちばん上に
**`⬇ CSV でダウンロード`** が出ます。クラス全員が1行ずつ、Excel で開ける形です。

| 列 | |
|---|---|
| なまえ・レベル・累計XP・正解・挑戦・正答率・コイン | 累計 |
| 学習時間(分)・学習日数・さいごにあそんだ日 | 累計 |
| 今月きた日・今月の問題・今月の正解・今月の時間(分) | 今月ぶん |

- **出せるほうが導入されやすく、実際には誰も出ていきません。**「うちの記録なのに
  取り出せない」と思わせないことのほうが、囲い込むより効きます。
- 先頭に BOM を付けてあるので、**Excel の日本語版でも名前が化けません**。
- 署名は子ども1人ぶんのリンクとは**別物**（`export|<クラス>`）。1人ぶんのリンクを
  クラス全員ぶんに読み替えることはできません。
- 引っ越し済みの行と先生の行は出しません。
- 検査は `server/test/carryover.test.mjs`（5項目・CSVの形、名前に `,` や `"` が
  入っても列がずれないこと、署名の取り違え）と `server/test/room.test.mjs` の
  「年度またぎ」（実ソケット・**子どもは引き継げない**・上書きしない）。

## つづけてもらうための3つ（`server/src/game/retention.js`）

**調べてから決めました。** 他社事例と、子ども英語教室の退会理由そのもののリサーチが
`docs/uspeak-retention.md` にあります（出典つき）。要点は3つ：

1. **退会は「見えない」から起きる。** 伸びは階段型で、最初の3〜6か月は「沈黙期」
   （子どもは英語を口に出さず、テストの点も動かない）。ここがいちばん辞めやすい。
2. **塾向け Comiru（4,000教室以上）で継続に効いているのは「退塾予備軍の早期発見」。**
   数字を見せるだけでは先生の行動は変わらない。**名指しで出す**と変わる。
3. **Duolingo のストリークは効く（D14 継続 +14%）が、効きすぎる。**
   「連続を伸ばすこと」が学ぶことより大事になる、という研究がある。

### ① きょうの気づき（先生コンソール）

先生コンソールを開くと、ボタンのすぐ下に出ます（**探させると読まれない**ので、
レポートのリンクと同じく見えるところに置いてあります）。

| 印 | 意味 | 出る条件 |
|---|---|---|
| ● 声をかけましょう | 今週のうちに | 21日以上 来ていない／沈黙期の子が14日以上／沈黙期の子のペースが落ちた |
| ○ 気にしておく | まだ声をかけるほどではない | 14日以上 来ていない／先月よりペースが6割を切った／はじめて3か月以内 |
| ✦ いいこと | **保護者に伝える機会** | 先月より1.4倍よく来ている |

- **他人とは比べません。** 出るのは全部「その子の先月とくらべて」で、教室の中の
  順位は作りません（順位は、下にいる子の保護者に見せられません）。
- **月の前半ではペースの話をしません**（4割を過ぎてから）。9月3日に「先月より
  少ない」と言っても、それはカレンダーの話でしかありません。
- **先月2日しか来ていない子は比べません**（比べる相手がいない）。
- **多すぎたら切ります**（既定12人）。30人ぶん並べた一覧は読まれません。
- **いま部屋にいる子は、保存ではなく部屋の側の数字で見ます。** 保存は折々にしか
  走らないので、目の前で遊んでいる子に「3週間来ていません」と出しかねません。
- しきい値は `retention.js` の頭にまとめてあります（`AWAY_CALL` = 21 など）。
  教室から「この子は違う」と言われたら、そこを直せます。

### ② 去年の同じ月（保護者レポート・マイページ・紙のPDF）

**13か月ぶん持っている意味は、ここにしか出ません。** 4月に「去年の4月」と並べられる
長さにしてあります。1年たっていない子には出しません（無い数字は出さない）。

- 差を**1文にして**から出します（「きた日が 3日 ふえました。正解率は 同じくらいです」）。
  数字だけ並べても読めませんし、減っていたときに責める文になりがちです。
- **1年つづけた教室にしか出せない画面**です。新規参入が明日コピーできる種類の差では
  ありません（`docs/uspeak-retention.md` の5）。

### ③ つづけた月数

「◯か月つづけています」。**日の連続ではなく「答えた月」の連続**です。

- **週1〜2回の教室の子に、毎日の連続を求めるのは設計のまちがい**です。
- **切れても何も言いません。** 「あと3時間で消えます」は出しません。出したいのは
  損失回避ではなく「自分はこれを続ける人だ」のほう（研究が「長持ちする」と
  言っているのはこちら）。
- 今月にまだ何もしていなくても切りません（月の1日に0と出るのは、その子が何かしたか
  どうかではなくカレンダーの都合です）。2か月から出します。

### 在籍の長さ

`first_seen`（記録の列。**初回保存で埋まります**）。古い記録には入っていないので、
その場合は**サーバーが初めて読んだ日**を入れます。月ごとの記録は13か月で落ちるので、
そこからでは「1年以上まえから居る」ことしか分かりません。

検査は `server/test/retention.test.mjs`（12項目・**しきい値のふるまいを名指しで**
測る。うるう年、月の前半、比べる相手がいない子、壊れた保存）と
`server/test/room.test.mjs` の「きょうの気づき」（実ソケット・名簿と一緒に降りてくる・
先生の行は出さない）。

## 競合と引き離すための8つ（教室の運営に入り込む記録）

**調べてから入れました。** 根拠と出典は `docs/uspeak-moat-2.md`。要点は、
コンテンツ（島・ゲーム）は資本で殴られ、AI 採点はもうコモディティで、**空いているのは
「教室の運営に入り込む記録」だけ**だということ。Comiru は「誰が来たか」を、学習アプリは
「何ができるか」を持ちますが、両方を1つの画面で持っているのはここだけです。

| # | なに | どこから開く | コード |
|---|---|---|---|
| ① | **教室のようす**（利用継続率・業界平均93〜97%との比較・今月まだの子・はじめて3か月未満・声かけの結果・英検の準会場） | 先生コンソール →「📄 保護者レポートのリンク」→「🏫 継続率と 英検の準会場」 | `game/classview.js`・`/class/:classCode?t=` |
| ② | **きょうの 5ふん**（どこからでも答えられる5問：読む3・聞く2）と **おうちの日** | マイページのいちばん上 | `game/quick5.js`・`client/dist/quick5.js`・`months.js` の `home` |
| ③ | **英検の目安と準会場の見込み**（10人以上で開ける） | 先生コンソール・保護者レポート・マイページ | `game/eiken-ready.js` |
| ④ | **中学の目安**（「中学1年生くらいの英語の問題に24問正解」） | 保護者レポート | `eiken-ready.js` の `SCHOOL`・`months.js` の `eg` |
| ⑤ | **先生のメモ**（保護者に見せる／先生だけ） | 先生コンソールで子どもの名前を押す | `game/notes.js` |
| ⑥ | **声かけの記録と、14日以内に戻ったか** | きょうの気づきの「声をかけた」 | `notes.js` の `call` |
| ⑦ | **面談メモ**（話すことを自動で並べる） | レポートのリンクの 🗣／子どもの画面の「面談メモを ひらく」 | `report.js` の `talkingPoints`・`?view=meet` |
| ⑧ | **学習の記録証**（印刷用の1枚） | 保護者レポートの「📜 学習の記録証」 | `report.js` の `certHtml`・`?format=cert` |

**言いすぎないための約束**（画面の言葉にもそのまま出ています）：

- **利用継続率は「来たか」で数えます**（月謝の在籍はこのサービスには分かりません）。
  前の月に1問でも答えた子のうち、その月にも答えた子の割合。今月（途中）は率に入れず、
  「先月来ていて今月まだの子」を名前で出します。人数が少ない月は「1人で大きく動きます」。
- **英検は合格の予想ではありません。** 島の練習問題の直近20問で、5級・4級は「よむ・きく」、
  3級は「よむ・きく・かく」が7割以上なら「練習で目安に届いた」（一次の中身に合わせています。
  3級の「はなす」は二次として別に出します）。**やさしい判定の○は数えません。**
  8問答えるまでは判断しません。1人は届いたいちばん上の級にだけ数えます。
- **声かけは因果を言いません。** 「声をかけたから戻った」とは書かず、起きたこと
  （14日以内にその子が戻ってきたか）だけを数えます。
- **先生のメモは既定で保護者に出ません。** 「保護者のレポートにのせる」を付けたものだけ
  （新しい順に3つ）。声かけは保護者には一切出ません。**CSV にはメモを全部出します**
  （教室が書いたものは教室のもの。`=` などで始まるセルは式にならないよう `'` を付けます）。
- **おうちの日は端末の申告ではありません。** 答えたとき部屋に先生（講師キーで入った人）が
  いたかを、サーバーが見て決めます。
- **記録証は公的な資格ではありません。** 期間・来た日・答えた問題と「英検の目安（練習で到達）」だけ。
- **日付は日本時間で出します**（サーバーは UTC で動くので、何も言わないと朝9時までの
  レポートが前の日付になっていました。今回あわせて直しています）。

**署名はリンクごとに別の文字を混ぜます。** 教室のようす（`class|<クラス>`）・CSV
（`export|<クラス>`）・1人ぶん（`<クラス>|<なまえ>`）はどれも別物で、どのリンクも
ほかの口には読み替えられません。面談メモと記録証は保護者レポートと中身が同じ
（先生だけのメモは入らない）なので、同じ署名で開きます。

**保存に足した列**（append-only・`store/records.js`）：`eiken_json`（級×技能の直近20問、
`'1'`/`'0'` の文字列）と `notes_json`（先生のメモと声かけ、1人60件・1件400字まで）。
月ごとの箱には `home`（おうちの日）と `eg`（英検の級ごとの正解）が増えました。
古い形の保存もそのまま読めます。

**先生コンソールのコマンド**（講師キーで守られた枠の中）：`note {name, text, share}`・
`called {name, why}`・`unnote {name, id}`・`notes {name}`。部屋にいない子にも書けます
（保存を直接書きかえます。部屋にいる子は部屋の側に書くので、戻ってきても消えません）。
いない名前には書けません（記録を勝手に作りません）。

**きょうの 5ふん**は位置で縛らないぶん、コインは英検の島と同じ1日の上限（`EIKEN_CAP`）に
入れます（どこからでも稼げる口を別に作らない）。級はその子が次にめざす級、きびしさは
教室の設定。採点・英検の目安への反映・学習ログは島と同じです。

検査：`server/test/eiken-ready.test.mjs`（7）・`notes.test.mjs`（5）・`classview.test.mjs`（5）・
`quick5.test.mjs`（3）・`months.test.mjs`（おうちの日と級ごと）・`carryover.test.mjs`（CSV の列と
式インジェクション）・`infra.test.mjs`（実ソケット・HTTP で通し：メモは先生だけ、見せるものだけ
保護者に、署名の取り違えは404）。実ブラウザは `npm run test:infra2`（33項目：390px と 1024px で
横にはみ出さない、きょうの5ふんが読む3・聞く2で終わる、「声をかけた」が「声かけ済み」に変わる、
メモが残る、教室のようすが声かけを数える）。`FIGURES=1` を付けると `docs/figures/infra2-*.jpg` を撮ります。

## 保護者レポートを紙で渡す（LaTeX PDF）

レポート画面（先生コンソールの `📄 保護者レポートのリンク` で配る、あの一人ひとりのページ）に
**「デザインされた PDF をひらく」** ボタンがあります。A4・2ページ。

- **1ページ目**：島の色の表紙。名前、レベル・XP・正解率の3つのリング、やったことの棒グラフ、レベルの印。
- **2ページ目**：ぜんぶの記録の表、**つぎの もくひょう**、そして「この数字はどこから来たのか」の説明。
- **中身は画面とまったく同じ数字**（`reportFor()` ひとつから、画面も紙も作っています）。
- **書いたメッセージや話した内容は載せません。** 学習の記録だけです。
- 先生コンソールの名簿リンクの横の 📄 からも、その子の PDF を直接ひらけます。

組んでいるのは **XeLaTeX**（`server/src/game/report-tex.js` が .tex を書き、`latex.js` が組みます）。
サーバーに LaTeX が無くても壊れません：

| サーバーの状態 | ボタンを押すと |
|---|---|
| LaTeX あり | PDF がひらく（1枚 約3秒） |
| LaTeX なし | 入れ方を書いたページ＋**`.tex` のダウンロード**（手もとで `xelatex` すれば同じ PDF） |

```sh
# サーバーに入れる（Debian / Ubuntu。開発環境ではこれで確認しました）
apt-get install -y --no-install-recommends \
  texlive-xetex texlive-lang-japanese texlive-lang-chinese fonts-noto-cjk

# Docker / Fly.io（既定では入れていません。イメージが 500MB ほど太るので）
fly deploy --build-arg WITH_LATEX=1
```

**フォントは あるものを使います。** Noto Sans CJK JP → Noto Sans JP → Yu Gothic → Meiryo →
Hiragino Sans → IPAexGothic → IPAGothic の順に探すので、Windows でも macOS でも
そのまま `xelatex` で組めます（どれも無ければ、何を入れればよいかを言って止まります）。
特定のフォントで組ませたいときは `REPORT_FONT=游ゴシック` のように指定してください。

`.tex` は画像も外部ファイルも使っていない1枚ものなので、**文面や色を学校で書き換えて**
そのまま組み直せます。急ぐときは、レポート画面をブラウザーの「印刷 → PDF に保存」でも
きれいに出ます（印刷用のスタイルを入れてあります）。

## 教室さま向けの説明資料（島とゲームのぜんぶ・PDF）

`docs/uspeak-guide.tex` → **`docs/uspeak-guide.pdf`**（A4・25ページ・画像43点）。
**いま U-Speak Roblox を使っている教室さま**に「何がどう違うのか」を説明するための資料です。
表紙・Roblox版との対照表・14の島を1島1ページ（島の写真＋**その島の実際の画面**）・
のりもの島とまちづくり島はもう1ページずつ（レース本番・建てているところ・同梱ゲーム）・
記録と保護者レポート・教室での運用・数字の一覧。

```sh
# 図を撮り直す（ブラウザを実際に動かして41枚。島は「昼になるまで待って」から撮ります）
cd server && node test/e2e/capture-figures.mjs
node test/e2e/capture-figures.mjs blockwild island-town   # 名前を含むものだけ撮り直す
node test/e2e/capture-report.mjs                          # 保護者レポートの見本2枚

cd docs && xelatex uspeak-guide.tex && xelatex uspeak-guide.tex
```

- 図は `docs/figures/*.jpg`。**すべて実際に動いているワールドから撮ったもの**で、手描きはありません。
- **画面は「遊んでいるところ」まで撮ります。** ウーピーと1往復してから撮った会話、
  実際に走っているレース（順位・ラップつき）、かぐを置いた部屋、ブロックを積んだひろば。
  そのために撮影用の手順がいくつか要ります：**レースはのりものを買ってからでないと始まらない**、
  **部屋とひろばは戸口（`spot.z - 0.65`）に立たないと入らない**、

  `capture-figures.mjs` にその理由ごと書いてあります。
- 島の写真は**必ず昼**に撮ります（空は世界の時計だけで決まるので、夜に走らせると14枚とも真っ暗になります）。
  `capture-figures.mjs` の `daylight()` が次の昼まで待ってから撮りはじめます。
- 保護者レポートの見本は**架空の子ども1人**を `reportFor()` → `reportTex()` → `xelatex` に通したもの。
  本番とまったく同じ道なので、見本と本物が食い違うことはありません。
- 文中の数字（問題数・値段・品数）は、すべて `client/dist/*.json` と
  `server/src/game/*-bank.json` の実データから拾っています。**足したら資料も直すこと。**

### 土台の機能の解説動画（ナレーションなし・字幕）

`docs/infra-cuts.json`（台本）から、`docs/make-infra-video.py` が作ります。


| 出るもの | |
|---|---|

| `docs/uspeak-infra-video.srt` | 焼き込みと同じ字幕。**動画はそのままで字幕だけ差し替えられます** |
| `docs/infra-video-script.md` | 台本（カットと秒数の一覧） |

紹介動画（上）と**考えかたが3つ違います**。

- **尺は「読む速さ」から決めます**（1秒5文字＋間）。声が無いので実測できません。
- **字幕が本文**なので、帯を高く・字を大きくしてあります（2行まで）。
- **見てほしいところを切り出して大きく映します**（`crop`）。声があれば
  「右下の…」と言えますが、無いので**その部分だけを出す**しかありません。
  **切り抜きは切らずに全部入れます**（contain）。覆う入れかた（cover）にすると、
  横に長い切り抜き——「5かげつ つづいてるよ」の帯のような——の左右が画面の外に出て、
  **指さす代わりに切り抜いたのに、その切り抜きが切れます**（一度そうなりました）。
- **無音のトラックを1本入れてあります。** 音の無い mp4 を「壊れている」と扱う
  再生機・変換があるためです。ナレーションを足すときはここを差し替えます。
  実機で録り直したものを `docs/clips/` に同じ名前で置けば、そのまま差し替わります。
- **録画のウーピーは絵のフクロウです。** 本物は mp4 の動画ですが、録画に使った Chromium に
  H.264 が入っていないので `character.js` が絵に切り替えます（そういう作りです）。
  教室の端末では動画のウーピーが出ます。口が動くのはどちらも同じです。
- 図は `docs/figures/`。PDF の資料（`docs/uspeak-guide.pdf`）と同じものです。
- **`in5: false` を付けたカットは5分版から落ちます。** `short` を書けば、5分版はそちらを読みます。

## 島の音（風と、昼と夜の BGM）

`client/dist/ambience.js` が全部です。鳴るものは2つだけです。

| | 中身 | どこから |
|---|---|---|
| 風 | ごく小さな風の音 | **ブラウザーが自分で作ります**（音のファイルはありません） |
| BGM | 昼の曲・夜の曲 | `client/dist/assets/bgm/day.mp3` / `night.mp3`（渡された音源をそのまま） |

**鳥と虫の鳴き声は作っていません。** 以前はブラウザーが自分でオシレーターを鳴らして
いましたが（昼は鳥、夜は虫）、どちらも結局は電子音で、後ろで「ピピピ」と鳴り続けるのが
耳につきました。曲が入ったいま、**時間帯を伝える仕事は BGM のほうが上手にやります**。

- **2曲は同時に流し、音量だけで混ぜます。** 時間帯で鳴らし分けると夕方のその一瞬で曲が
  変わり、そこだけ場面転換のように聞こえます。世界の時計は昼から夜へなめらかに動くので、
  音もそう動かします（夕方は2曲が重なり、夜になりきったときに昼の曲は消えています）。
  混ぜかたは**等電力**（cos / sin）です。足して1にすると、ちょうど半分のところで音が痩せます。
- **音量は `<audio>` の `volume` ではなく Web Audio の GainNode で扱います。**
  **iPad Safari は `audio.volume` を無視します**（読めるが効かない）。あそこで混ぜると、
  教室で使う端末でだけ効かない、というたちの悪い出かたをします。
- **曲を読みに行くのは最初のタッチのあと。** 1曲2.8MB あるので、音を切っている教室に
  黙って5MB 落とさせません。`arm()`（`game.js` が `pointerdown` / `keydown` で呼ぶ）が入口です。
- **全画面の別ゲーム・グランプリが上がっている間は黙ります**（`ambience.setBusy()`・
  `game.js` のフレームループが島を止めるのと同じ1か所）。あちらにはあちらの音があるので、
  重ねると教室ではただうるさいだけです。曲は**止めます**（gain 0 のまま流し続けると、
  音は出ないのに iPad は mp3 を解き続けて電池が減ります）。
- **風の音は曲の10分の1**（`WIND_LEVEL = 0.05`）。曲が入る前は 0.5 で、単体なら気に
  なりませんでしたが、曲と重なると後ろの「ゴー」が曲を塗りつぶします。ここは
  「聞こえる音」ではなく**「静かすぎないための音」**でよい、という置きかたです。
- **♫ ボタンは全部に効きます**（master の GainNode に集めてあるため）。
- **差し替えるときは同じ名前で上書きし、`assets/bgm/SOURCE.json` のバイト数と sha256 も
  書き直すこと。** `client/tests/regression.mjs` が毎回突き合わせ、
  **`ambience.js` がその名前を指しているかも見ます**（曲名を変えて島を無音にしたまま
  出るのを防ぐため）。同梱ゲームと同じ扱いです。
- 検査は `server/test/e2e/browser-bgm.mjs`（実ブラウザ・13項目）。**測っているのは
  GainNode の値**で、`volume` に書き換えた直しはここで落ちます。時刻は世界時計の出口
  （`game.js` の `worldClock(net.night.update(…))`）に差し込んで動かします（11分待てないため）。

## 何MB流れるか（実測）

**「ファイルを全部足すと何MB」では答えになりません。** 同梱ゲームは開くまで1バイトも
落ちてきませんし、BGM は最初のタッチのあと、ウーピーの動画は家に入って初めて、
ガイドの写真は開いているページの分だけ落ちます。知りたいのは
**「授業で1人あたり何MB流れるか」**なので、順番にさわって測りました。

```sh
cd server && node test/e2e/measure-weight.mjs
```

| さわったところ | 流れたバイト |
|---|---|
| ページを開く（すがたをえらぶまで） | **2.64 MB** |
| クラスに入る（島が建つ・BGM 1曲） | **2.86 MB** |
| 「?」ガイドを5ページめくる | 0.41 MB |
| さかなつり・ワールドマップ・マイページ | **0.00 MB**（もう落ちている） |
| 島を4つまわる | **0.00 MB**（同じ） |
| 英会話島でウーピーと話す（動画2本） | 2.91 MB |
| AURORA KART をひらく | 1.52 MB |
| BLOCKWILD をひらく | 1.62 MB |
| もう片方の BGM（空が変わるとき） | 2.86 MB |
| **ぜんぶさわった合計** | **14.79 MB** |

**ふつうの授業なら 5〜6 MB**です（開いて、入って、島をまわる）。動画つきの英会話島と
別ゲームまで行って、やっと15MBです。2回目からは Cache-Control で
**同梱ゲームと写真と音は聞きに行きません**（上の表を参照）。

重いファイルの上位は `day.mp3` / `night.mp3`（各2.85MB）、`talking.mp4` / `idle.mp4`
（1.5MB / 1.4MB）、`three.module.js`（1.27MB）です。

- **BGM は2曲を同時に落としません**（`ambience.js`）。いま鳴るほうだけを落とし、
  もう片方は**空が変わりはじめてから**取りに行きます。夕方は120秒あるので十分間に合い、
  そのぶん授業のはじめに流れるのが 5.7MB → 2.86MB に半分になりました。
- もっと減らしたいときは、**mp3 のビットレートを落とす**のがいちばん効きます
  （いまは128kbps。教室の iPad のスピーカーなら 96kbps でも差は分かりません）。
  渡された音源そのままにしてあるので、そこは相談させてください。

## 出したのに古いものが出るとき（ブラウザのキャッシュ）

**このゲームのファイル名にはバージョンが入っていません**（`game.js` は毎回 `game.js`）。
そのため配信の持たせかたを間違えると、デプロイ直後の一定時間、教室の iPad には
古い `net-client.js` が出たままになります（実際に起きました）。

いまはこう分けてあります（`server/src/index.js`・`server/test/static.test.mjs` が検査）。

| ファイル | Cache-Control | 意味 |
|---|---|---|
| 自分たちの `.js` `.css` `.html` `.json` | `no-cache` | **毎回サーバーに聞く。** 変わっていなければ ETag で 304（中身は流れません） |
| 同梱ゲーム（`racers/` `blockwild/` `puyo/` `suika/` `assets/` `vendor/`） | `max-age=86400` | 丸ごと差し替えるまで変わらない。1本で何百ファイルあるので持たせます |

それでも古いものが出るときは、**強制再読み込み**を試してください。

```
Windows … Ctrl + Shift + R      iPad Safari … 「履歴と Web サイトデータを消去」
```

**デプロイが本当に入ったかは、ファイルを直接見るのが早いです。**

```powershell
curl.exe -I https://uspeak-multiplayer.fly.dev/guest-dock.js     # 200 なら入っています
```

## おつかいクエスト（おつかい島を歩くAI英会話）

**おつかい島**を歩いてやる「おつかい」です。判定・報酬・学習ログはサーバーが確定します。
詳細と運用は `docs/AI_MISSION.md` を参照してください。

```
① おつかい広場でミアから受け取る  →  ② お店まで歩いて英語で話す  →  ③ 広場にとどけてコイン
```

3つの区間はどれも、アバターがその場所に立っていることをサーバーが確認してから進みます。
一覧から選んでも行き先が決まるだけで、会話は始まりません。メニューだけでは完了できません。
（座標はクライアント申告なので不正の完全な防止ではありません。詳細は `docs/AI_MISSION.md`）

| 項目 | 実装 |
|---|---|
| 島 | `missions.json` の `island`（広場＋お店9か所）。クライアントの地形もサーバーの位置判定も同じ座標 |

| AI | プロバイダをアダプタで分離。`OPENAI_API_KEY` 未設定なら台本パートナーで動作し、API料金ゼロ |
| サーバー権威 | AIの返答も検証。存在しないお題IDは破棄、達成の取り消し不可、完了はサーバーが再計算 |
| 位置の確認 | 受け取り・会話・とどけの3つとも、島の該当地点から半径5m（＋余裕1.5m）以内でなければ `too far` |
| 報酬 | とどけて初めてコインとスタンプ。`economy` の `award` はサーバー専用で、クライアントからは呼べない |
| 先生 | 先生コンソールで「今日のおつかい」を指定。クラス全員の画面に出る |
| コスト管理 | 1返答のトークン上限、連打制限、1日の発話上限、1ミッションの往復上限 |
| 安全 | 個人情報を聞かない、AIだと明かさない、級ごとの語彙制限、全発話をログに記録 |


## 左下の操作は「スティック」（十字キーをやめました）

タッチ端末の移動は、**まるいスティックを指で倒します**（Roblox のモバイルと同じ形）。
以前は ↑←↓→ の4つのボタンでした。

**やめた理由は2つです。**

1. **斜めに歩けない。** 2つ同時押しは大人の指でも難しく、子どもはまず押しません。
   島の道は斜めに走っているので、これは「歩きにくい」としてそのまま出ます。
2. **速さが2段階しかない。** 押しているか、いないか。そっと近づくことができません。

スティックは**倒した向きと、倒した量の両方**を返すので、どちらも解けます。
倒し切れば走り、少しだけ倒せばゆっくり歩きます。

- 中身は `client/dist/stick.js`。返すのは `{x, z, mag}` だけで、**キーには変換しません**
  （8方向のキーに丸めると、せっかくの倒した量が捨てられて十字キーに戻ります）。
- **パソコンは今までどおり**（WASD と矢印キー）。スティックは `pointer: coarse` の
  端末にだけ出ます。
- **「◯◯と話す」は右下に寄せました。** 左下にスティックが座ったので、狭い縦画面では
  真ん中にいると重なります（実は十字キーの頃から重なっていました）。左が「動かす」、
  右が「話す」で、指の役割が左右に分かれます。
- 検査は `server/test/e2e/browser-stick.mjs`（実ブラウザ・指で倒して本当に歩くか）と
  `npm run test:layout`（5サイズ × 全画面の重なり）。

## スマホ・タブレット対応

`client/dist/mobile.css` が端末サイズ別の調整をまとめて担当します。デスクトップの見た目は変えていません。

| 直した点 | 内容 |
|---|---|
| 移動ボタンが出ない | 画面幅600px以下でしか表示されず、iPad と横向きスマホでは指で歩けなかった。タッチ端末なら常に表示するよう変更 |
| ホットバーの見切れ | 画面下のメニューが16pxはみ出していた。中央寄せのレイアウトに変更して全体を表示 |
| 右側ボタンの画面外配置 | 地図・カメラ・RPG・釣り・図鑑が固定の縦位置で並び、横向きでは画面外に出ていた。1本の縦並び（`.right-rail`）にまとめ、入り切らない場合はスクロール |
| クエストパネルの重なり | 内容が伸びて移動ボタンに重なっていた。高さに上限を付けてスクロール |
| ノッチ・ホームバー | `env(safe-area-inset-*)` で iPhone の切り欠きを回避 |
| マルチプレイUI | 接続状況の表示を「● 3人」に圧縮し、チャットと先生ボタンを移動ボタンと同じ帯の反対側へ配置 |

検証は5サイズ（iPhone 縦横、小型スマホ、iPad 縦横）で自動化してあります。

```sh
cd server && npm run test:layout
```

はみ出しと要素の重なりを検出し、`server/loadtest-results/layout-*.png` にスクリーンショットを保存します。

## 既知の制約

- 問題文・選択肢の生成はクライアント側。データファイルを読める人が「常に正解を選ぶ」ことは防げない（正誤・コインの改ざんは防止）。
- ルームはサーバープロセスのメモリ上にあるため、Fly のマシンは 1 台構成（`fly.toml` の `[deploy]`）。
- 通話は2種類。建物の中は 6 人（ブラウザー同士の直結）、おはなし島のひろばは 100 人（SFU）。
  屋外はおはなし島以外 通話にならない。
- Colyseus は 0.15 系に固定（サーバー・クライアント SDK とも）。0.16 以降はコールバック API が変わるため、更新時は `net-client.js` の `onAdd/onChange/listen` を見直す。
